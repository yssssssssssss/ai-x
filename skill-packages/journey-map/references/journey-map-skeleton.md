## 一、用户旅程图（逐张，表格网格）

每一类用户一张图。**阶段为列、维度为行**（与常见旅程图朝向一致，便于横向看完整历程、纵向看单阶段全貌）。先写角色头部，再上表格，情绪曲线单独一行。

```
## 旅程图 [①]：[**场景命名**——朗朗上口，如「置办新家全套采购」「旧机急换」「复购认准款」；**不用"研究型"这类人物特征名**]

> 一句话心智 / 典型场景：「[这类用户的核心心态，如『长期使用，一步到位买好的』]」
> 适用场景：[如 新房配置 / 旧机更换 / 帮父母买]　｜　支撑：[用户 A、用户 E（已匿名）／ 或 综合 N 位同型受访者]（provenance 放这行，**别进单元格**）

| 维度＼阶段 | [阶段1：需求产生] | [阶段2：信息收集] | [阶段3：挑选对比] | [阶段4：下单付款] | [阶段5：收货安装] |
|---|---|---|---|---|---|
| **目标** | […] | […] | […] | […] | […] |
| **行为** Actions | [几句关键动作（过程），如「把心仪的 4–5 款加进购物车，反复并排比参数和价格」；有循环/跳转就写成带箭头步骤流「看 A → 看 B → ↩回到 A 比价」] | … | … | … | … |
| **触点** Touchpoints | [触点：在这步的角色 / 用户得到啥，如「评价区：想找真实差评，翻到的多是泛泛好评」——别照搬行为动词] | … | … | … | … |
| **想法** Thoughts | ["第一人称原话，已匿名" + 没明说的 Think；**优先带细节/数字**，如「尺码助手的码和商家尺码表对不上」胜过「尺码不清晰」] | … | … | … | … |
| **情绪** Emotions | [emoji + 档位，见下] | … | … | … | … |
| **痛点/需求** Pain Points | [写具体不笼统：「表层：评价多是'还不错'泛泛之词、缺能帮决策的细节」「深层：要确信'这款就对'」] | … | … | … | … |
| **诉求**（可选） | [核心价值点，如"确定性/省心"] | … | … | … | … |
| **机会点** Opportunities | [一句话写清做什么、尽量落到触点；标"待共创"] | … | … | … | … |

**情绪曲线**（只标有情绪证据的环节；找低谷=痛点 / 高峰=爽点）：
[阶段1] 🙂 中　→　[阶段2] 😣 低谷　→　[阶段3] 😐 中低　→　[阶段4] 🙁 偏低　→　[阶段5] 😀 高峰
（档位建议：😀高 / 🙂中高 / 😐中 / 🙁中低 / 😣低；无情绪证据的环节标"—（材料未覆盖）"，不硬标）

> 标注：[本图哪些阶段/情绪基于 draft 正典 / 因材料不足而假设 / 机会点待共创，在此就地标一句]
```

写法约束：
- **完整句子、分条**：每个要点写成一句**能读通的话**（长短皆可，别只堆零碎短语/名词），多个要点分多条（HTML 自动 bullet）。
- **各行有区分度、别雷同**：行为 = 用户做了什么（过程）；触点 = 哪个触点、在那里发生或得到什么（换触点视角，别照抄行为的动词）；想法 = 心里怎么想；痛点 = 具体卡在哪 + 深层需求。**同一件事别在四行里换皮重复说**。
- **行为要具体丰富、能带流程**：按过程写出几句关键动作（行为是主干）；有循环 / 跨渠道跳转 / 分支就写成**带箭头步骤流**（「看 A → 看 B → ↩回到 A」「本站不全 → ⇢跳外部 → 再回来」），别压成并列要点、也别只写一句笼统话。
- **痛点 ↔ 机会点尽量 1:1**：每条痛点对一个**具体、可执行**的机会点改造、落到触点，别一格堆一串泛泛点；优先级清单里保持这种一一对齐。
- **痛点要具体、不笼统**：把问题写到细节（反例：「评价没参考」太空泛；正例：「评价多是'还不错'式泛泛之词，缺能帮决策的真实细节」），再用 user-insight 挖到深层需求（「表层：…」「深层：…」）。
- **触点写"在此发生什么"**：每个触点写「触点：扮演什么角色 / 用户在那得到啥」（「评价区：想找真实差评，翻到的多是泛泛好评」），**别只甩触点名**。
- **分图单位 = 场景事件、不是人**：一张图 = 一个**场景**下的一类虚拟典型用户；**同一受访者可跨多张图**（不同场景）；图名用**场景命名**、不用"研究型"这类人物特征名。格子里写**这一类用户在该场景的共性**，**不放 A/B/C 个体编号**；同场景小差异综合成一句共性、场景不同就另起一张图；provenance 放**图头部 support**（可具名「用户 A、用户 E」或写计数「综合 2 位」）或脚注/优先级表，**别撒进格子**。
- **先定单一场景主轴、避免混轴**：只用一个互斥维度切场景，其余维度作叠加变体标注，别让一个真实行为同时落进两张图。
- **行的取舍**：必要行（阶段/场景、行为、痛点·需求、机会点）一定有；灵活行（目标、触点、想法、情绪、诉求、标杆）按材料增减。**撑不起的行宁可不列，也不编**。
- **每个格子可回溯材料**：行为、触点、原话、情绪、痛点都点得到出处（共性来自哪几位用户），绝不为"完整/好看"虚构（SKILL.md 纪律 4）。
- **画的是用户场景不是功能模块**；阶段主线按**行为顺序**（可局部循环），不是时间轴。
- **多张图之间要场景上真不同**：若两张图的阶段主线、行为、触点几乎一样、只是需求措辞有别，说明不该拆——合并成一张、用**共性概括差异**（不按个体编号散点）。
- **情绪曲线**只对有证据的环节标，别为画出漂亮曲线硬给每格打分。

## 五、形态示意（仅示范"长什么样"，**勿照抄内容**——务必按真实材料重写）

> 下例是凭空编的格式演示，不是任何正典内容，也不针对真实项目。看完格式即弃。

```
## 旅程图研判
- 研究目标：用户从产生洗衣机购买需求到收货安装的端到端体验
- 材料：6 份用户访谈；走洞察绘制
- 画几张图及依据：共 2 张。按"研究深度 × 购买动机"分出「全面研究型」「即时应急型」——前者跨平台深度比参数、后者旧机坏了急着换，二者信息收集与挑选对比阶段的行为、触点、情绪差异显著 → 分 2 张
- 分型来源：本次轻量分型（建议后续跑 generate-persona 补全角色）
- 阶段主线：需求产生 → 信息收集 → 挑选对比 → 下单付款 → 收货安装

## 旅程图 ①：全面研究型
> 心智：「这台要用很多年，必须一步到位买个好的。」｜适用：新房配置/旧机升级｜支撑：用户 A、用户 E（已匿名）

| 维度＼阶段 | 需求产生 | 信息收集 | 挑选对比 | 下单付款 | 收货安装 |

| 目标 | 想趁装修一步到位，买一台能长期用的好洗衣机。 | 把洗衣机的门道搞懂，弄清自己到底该看哪些点。 | 在多款里挑出最匹配自家需求的 1–2 款。 | 在确认是好价格的前提下把心仪机型买下来。 | 按自己的装修节奏收货，并顺利装好。 |

| 想法 | "这台要用很多年，必须一步到位、不能买错。" | "这些专业名词我看不懂，也不知道它到底影响什么。" | "几款对比着看，看完一个就忘了上一个差在哪。" | "我也不知道现在是不是底价，万一买完就降价怎么办。" | "幸好能延迟收货，不然新房没入住根本没法收。" |
```

## 六、可视化 spec（喂给 `scripts/render_journey_map.py`，第 5 步 B 出图用）

把已经画好的旅程图整理成下面这份 JSON（**内容与 Markdown 完全一致、同样不编造**），存成 `journey-map.spec.json`，再运行渲染器产出自包含 HTML：

```
python scripts/render_journey_map.py journey-map.spec.json journey-map.html
```

渲染器零依赖、纯标准库，字段缺失会优雅降级。结构：

```json

```

字段要点：
- **`cells` 的每个元素可以是「字符串」或「字符串数组」**——**有多个要点时务必用数组**（每条一个要点），渲染器会分条 bullet 罗列；单一要点用字符串即可。每条都用**完整句子**（别只堆零碎短语）；`priorities[].need`、`priorities[].opportunity` 同样支持数组分条。
- **各行写出区分度、别雷同**：行为 = 用户做了什么（过程）；触点 = 哪个触点、它的角色 / 用户在那得到啥（别照搬行为动词）；想法 = 第一人称心声；痛点 = **具体**问题（别笼统，如「评价多是'还不错'泛泛之词、缺能帮决策的细节」）+ 深层需求。行为可写成**带箭头步骤流**（「看 A → 看 B → ↩回到 A」，纯文本渲染即可、**无需新字段**）；**痛点与机会点尽量 1:1 对齐**、机会点落到具体触点。
- `rows[].key` 决定配色：`goal / action / touchpoint / thought / pain(或 need) / opportunity / demand(诉求)`；`cells` 长度对齐 `stages`，缺的填 `""`。可只放本次有内容的行（必要行：行为/痛点/机会点）。
- `emotion.levels`：**1=低谷 … 5=高峰；只对有情绪证据的环节给值，无证据填 `null`**（渲染成断点 + "无情绪证据"）——绝不为画出漂亮曲线而硬给每格打分（呼应 SKILL.md 纪律 4）。
- `maps` 可 1..N 张；多张自动带顶部导航（对应"画几张图"的判断）。
- `priorities` 可省；`priority` 取「高/中/低」自动上色。
- spec 是**中间产物**，可与 `.md`/`.html` 一起留在交付目录；它**不替代** Markdown 文档，二者内容必须一致。
