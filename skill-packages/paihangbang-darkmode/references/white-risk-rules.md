白色前景与大面积白底风险规则
目标

暗黑适配验收时，不能用“白色数量”判断质量。白色前景是暗黑界面中的正常元素；真正的问题是大面积日间白底。

三类白色
类型	示例	处理
合理白色前景	TEXT、icon、状态栏、返回/更多、顶部导航、反白按钮里的文字/icon	保留，不算风险
可疑浅色组件面	tab/chip/button 小面积底、玻璃态面、选中态组件面	结合场景判断，默认不强改
错误大面积白底	页面根背景、内容区背景、商品/榜单卡片背景、大面积容器底	必须处理
风险判定

只有同时满足以下条件，才算 largeLightBackgroundRisk：

不是 TEXT。
不是小 icon / 小矢量。
不是 head-ui-inverse。
不是 frozen 区。
key === fills。
面积大于阈值，默认 width * height > 1000。
亮度高，默认 luminance > 0.75。
opacity 高，默认 opacity > 0.55。
不应计为风险
#ffffff 文本。
#ffffff 状态栏 / 顶导航 / 返回 / 更多 / 搜索图标。
#e1e6eb 强文本。
#ffffffe6 反白前景或 icon。
商品图本身的白色背景。
运营头图/切图里的白色、金色、红色。
被上层有效暗色 paint 覆盖的下层旧 #ffffff fill，例如 #1f2226 + #ffffff、#40262a + #ffebf1、#2a2f36 + #f0f2f7 + #ffffff。验收以视觉可见 paint 为准。
统一暗黑目标底色

频道、强暗黑频道、金榜、真榜、O2O 榜单统一使用：

层级	目标色
页面根 / feed 外底	#14171a
Tab 行 / 页面承托 / 卡片 / 楼层	#1f2226
chip / 块状 Tab / 小方块	#2a2f36

#000000 不再作为默认页面底，除非用户明确指定纯黑视觉。

排行榜/金榜类特别规则

如果正确样本只是“日间稿绑定 V16 后切暗色模式”，说明该类页面优先策略是：

V16 light token 重绑 → 切暗色模式 → 只修大面积白底


不要对文字、标签、小组件做大规模 fallback。fallback 仅用于：

大面积白底未随 V16 暗色变化。
边框/蒙层透明度明显错误。
产品化 UI 明确无法绑定 V16，但需要输出可用视觉稿。
报告口径

报告应区分：

whiteForegroundCount：白色前景数量，仅观察，不算失败。
largeLightBackgroundRisk：大面积浅底风险，需要处理。
frozenWhiteCount：冻结区白色，不算失败。

不要输出“白色很多所以不合格”。
