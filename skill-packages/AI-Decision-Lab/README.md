# AI Decision Lab

AI Decision Lab 用于在正式评审前，对单稿、多稿方案或交互流程进行基于用户、业务场景、设计专家和数据专家视角的结构化预评审，帮助设计师更早发现风险、对齐方案取舍依据。

## 适用场景

- 单稿评审：判断一版设计方案是否存在明显理解、路径、转化或视觉风险。
- 多稿对比：比较多个方案在当前用户、业务场景和关注重点下的优劣与取舍。
- 多页面 / 多状态流程评审：判断用户路径是否连续，哪里可能出现理解断点、行动断点或转化流失。
- 局部区域评审：聚焦商卡、头图、Tab、导航、筛选栏、按钮 / 转化区等局部模块。

## 核心能力

- 用户视角：基于人群画像判断用户第一眼关注、理解阻力和可能行动。
- 业务场景视角：基于排行榜、新品、PLUS 等场景画像，识别用户任务和关键决策条件。
- 设计专家：基于目标导向设计、HIG、Material Design、格式塔、菲茨定律、尼尔森原则等进行设计判断。
- 数据专家：优先引用已验证实验结论；没有直接结论时，按相近场景结论、跨场景通用规律和置信度进行推理。


- `SKILL.md`：Zero Skill 主文件，包含评审流程、交互规则、输出结构和评审边界。
- `cache/joyspace-knowledge.json`：随包 Joyspace 知识缓存，用于在无法实时读取 Joyspace 时提供评审规范、人群画像、业务场景画像、专家画像和数据结论。

## 使用方式

在 Zero 中调用 `AI Decision Lab` 后，直接上传要评审的截图。Skill 会先确认人群画像、业务场景和关注重点，再输出结构化评审结论。

首次调用时会提示：

```text
您好，我是AI设计评审助手，可以帮您从用户视角、业务场景视角、设计专家和数据专家四个角度评审页面、多稿方案或交互链路。

请直接上传要评审的截图。我会先确认人群画像、业务场景和关注重点，再输出结构化评审结论。
```

## 评审边界

- 评审前必须确认人群画像、业务场景、关注重点和专家覆盖。
- 业务场景不作为事后“场景修正”，而是作为前置条件融合到人群评审和专家评审中。
- 商卡、商品卡、菜品卡、Tab、导航等模块中的标题、价格、图片、商品 / 菜品选择、品类、卖点文案等默认视为后期配置或占位内容；除非明确要求评内容配置，否则只评结构、样式、信息优先级和扫读效率。
- 数据专家必须区分直接结论、可迁移结论、跨场景通用结论和推测性判断，不能把推测当作事实。
