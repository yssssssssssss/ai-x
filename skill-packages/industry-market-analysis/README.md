# 行业市场分析工作流

> 京东体验设计团队通用工作流,用于任何品类频道的市场分析调研。

## 这是什么

一套**可复用的行业分析文档包**。设计师拿着它,能用一套固定的思考内核,把任意品类频道的行业问题想透——小到在对话里碰一个想法、拆一个竞品,大到产出一份能上会立项的完整报告,为频道改版决策提供支撑。

**内核固定,外形随场景**(第一原则):
- **锁死的是「怎么想」** —— 10 维框架、京东设计哲学做最高裁判、量化必有出处/绝不编数、落到设计师能开工。每次调用都不打折。
- **释放的是「产出长什么样」** —— 从"对话里直接给结论/对比表/灰阶线框",到一份 `.md` 底稿,到自包含可离线的 HTML 汇报页,按用户当下要什么伸缩,**不强制每次都出报告**。

**产出光谱(按调用成本从轻到重)**:

| 档 | 用户要什么 | 产出形式 |
|---|---|---|
| **第0档·对话态** | 碰想法、要个判断、拆一个竞品模块 | 就在对话里给结论/对比/灰阶线框,不落文件 |
| **A·一次产出** | 快速摸底,先拿到能讲的结论 | 一份 `.md`,三档结论都给到 |
| **B·分阶段精做** | 立项/年度规划/上会汇报 | 走完阶段后渲染 HTML 汇报页(5 Tab),底稿先用 `.md` 跑、自检通过再渲染 |

> HTML 汇报页不是每次的默认终点,而是**汇报/立项场景才触发的重档产出**——一段对话没法甩给决策层看,这种场景才需要"可离线打开、一眼可辨同一工作流产出"的结构化交付物。规范见 `阶段说明/阶段8-报告装配与自检.md`。

## 何时用

只要是"用行业/竞品/设计哲学的专业视角想品类频道的事",就可以用——无论轻重:

- 在对话里**碰一个想法**、拆一个竞品模块、要一张对比表或灰阶线框(→ 第0档,直接聊)
- 接到新品类频道改版需求,需要摸清赛道
- 做频道年度规划,需要对齐行业趋势
- 汇报中要给决策层展示"我们凭什么这么改"(→ 这一条才需要走到 B 档出 HTML)
- 想在设计前建立品类的"世界观"(用户、竞品、机会、视觉语言)

## 何时不用

- 和品类频道的行业/竞品/体验/设计**完全无关**的问题(纯技术实现、纯文案、跟设计无关的杂务)
- 已有非常成熟的品类认知,只想借某个环节 → 直接取「阶段 3 京东内诊」或「阶段 6 设计语言推导」单跑

> 过去"单点优化、快速体检、查数据"被列为"不用",其实是**不该被逼着出一份重报告**——现在都走**第0档对话态**,照样用这套框架和设计哲学,只是产出留在对话里。`参考资料/频道体验走查checklist.md`(10 分钟频道体检)是第0档的趁手工具。

## 三种用法(按调用成本从轻到重)

**第0档 · 对话态(最轻)** —— 你只是碰想法、要个判断、拆一个竞品模块、问某点违反哪条设计原则。**直接在对话里回答**:该拆竞品就拆到模块级、该给对比就上四要素对比表、该给设计动作就配灰阶线框。内核不打折——照样锚定京东设计哲学、量化必有出处、拿不到的数据标 `【待补】` 绝不编数——只是产出留在对话里,不落文件、不起流程。适合高频、即时的专业咨询。

**用法 A · 一次产出(中)** —— 你只给**品类 + 线上产品链接/依据**,让 AI 一次产出一份**三档结论都给到**的 `.md`,不用反复跑。
- 用 `模板/报告模板-三档合一.md`
- 报告顶部就是「轻/中/重」三档结论速览,决策层、立项方、战略方各取所需
- AI 拿不到的数据(App 交互实况、内部 KPI、一手访谈)会标 `【待补】`**绝不编数**,并附「升档补数清单」——补数是增量追加,不重跑
- 适合:快速起步、先拿到能讲的结论、再按需补实

**用法 B · 分阶段精做(重)** —— 按 1→8 阶段人机配合走完,产出单一档位的精修报告,并在阶段8渲染成 HTML 汇报页。见下方「快速上手 5 步」。
- 适合:已确定档位、要交付立项/战略级报告、有条件补齐截图和内部数据

> 三档可衔接:先在对话里(第0档)碰清楚方向 → 用 A 摸底 → 再用 B 对重点章节精做。**从哪档起、要不要往上升,由你当下的需求决定,不默认冲着出 HTML 走。**

## 快速上手 5 步(用法 B)

1. **读**:`工作流总览.md`(10 分钟了解全貌)
2. **选**:`参考资料/三档深度对照表.md` 选一个档位(轻/中/重)
3. **建**:在 Desktop 建品类目录,如 `宠物行业分析/`,把频道现状截图/竞品截图放进去
4. **跑**:按 `阶段说明/` 里 1→8 顺序走。每份阶段文档都是自包含的:目标 → 输入 → 动作 → 产出 → 自检
5. **装**:走到阶段 8,用 `模板/报告模板-{档位}.md` 装配最终报告(含第5 Tab 品类差异资产)

## 目录导航

```
├── README.md                       ← 你在这
├── 工作流总览.md                    ← 10 维度 + 三档 + 8 阶段全景
├── 阶段说明/                        ← 按 1-8 顺序执行(用法 B)
├── 参考资料/                        ← 按需查阅
│   ├── 京东设计哲学(平台基线).md   ← 最高裁判:诊断/策略/设计都基于它
│   ├── 第0档-对话态怎么答.md         ← 不起流程时怎么答:四条底线 + 三个即时产出物
│   └── 频道体验走查checklist.md     ← 轻量工具:10 分钟频道体验快速体检
├── 模板/                            ← 报告模板(含「三档合一」一次产出模板)
└── 框架图.html                      ← 对外/新人的可视化「一页纸名片」(非执行依据,内容以本文档+阶段说明为准)
```

> **框架图.html 的定位**:一张对外介绍 / 新人 onboarding 用的可视化名片——一眼看懂"能产出什么(三类)+ 8 阶段怎么做 + 覆盖什么"。它是**展示物,不是执行依据**:执行看 `阶段说明/`,全貌看 `工作流总览.md`。仅在**结构级变动**(改名/Tab调序/增删阶段或资产段)后同步更新,纯视觉微调不必回改。它也是全品类统一配色 token 的视觉源头。

## 10 大维度覆盖(全景)

- **A. 宏观背景** — 市场规模、政策、技术、社会文化
- **B. 用户洞察** — 画像、场景、决策链路、痛点
- **C. 供给侧** — 货品结构、品牌格局、价格带、内容阵地
- **D. 竞品与参考** — 直接竞品、内容参考、跨行业、海外
- **E. 京东内部诊断** — 频道现状、KPI、体验拆解、舆情
- **F. 机会与策略** — Gap 分析、差异化、创新方向、优先级
- **G. 设计落地** — 设计原则、视觉语言、交互模式(**平台基线 + 行业增量**,继承平台设计系统,不脱离平台规范)
- **H. 可衡量指标** — 成功指标、ROI 预判、风险假设
- **I. 方法论与附录** — 数据源、方法说明、引用规范
- **J. 商业与经营逻辑** — 商业/经营模式、业务战略、运营策略、售卖模式与逻辑、选品逻辑(每条带"设计含义")

## 核心原则

- **平台哲学是最高裁判**:体验诊断、机会分析、策略输出、设计推导,每一步都要能回溯到京东零售设计哲学(智性设计 + 4 价值观 + 6 原则)——诊断问"违反哪条原则",定位问"站哪条价值观",设计问"继承还是增量"。详见 `参考资料/京东设计哲学(平台基线).md`。
- **量化必有出处**:每个 % / ¥ / 增速要么带引用,要么标"估算·待核实"
- **一句话结论**:每大节末浓缩成 1 句,便于汇报引用
- **保留品类特色**:视觉方向来自品类属性推导,不硬套通用风格
- **务实优先级**:短 1-2 月 / 中 3-6 月 / 长 6+ 月,每档都是可交付动作
- **产出形式随档位,不散落**:第0档留在对话里、不落文件;A/B 档只产 1 份最终交付(`.md` 或 HTML),中间产物不散落。别默认冲着出 HTML,也别在轻场景硬造文件。

## 反馈与迭代

工作流会随着实践迭代。跑完一份报告,把踩到的坑记录到 `阶段说明/` 对应文件的"常见坑"一节。
