# 阶段 1 · 澄清与档位

> 花 10-30 分钟把范围钉死,后面 90% 的返工都能避免。

## 目标

在正式动手前,回答清楚 4 个问题:**做什么品类、做多深、聚焦什么、素材在哪**。

## 前置输入

- 立项来源(接到什么需求)
- 业务方期望的交付时间
- 你手头已有的品类背景知识
- (如有)已跑过的相关分析文档

## 具体动作

### Step 1 · 品类确认(5 分钟)

在纸上或文档里写下:

```
本次分析的品类是:___________
细化到哪一层?(如"图书"→"图书"or"图书·少儿"or"图书·教辅")

排除项:哪些子类不在本次范围?
______________________________________
```

**避坑**:含糊的"母婴"和精准的"母婴·奶粉"分析深度完全不同。宁细勿宽。

### Step 2 · 档位选择(5 分钟)

打开 `参考资料/三档深度对照表.md`,对照场景选一档。

```
本次档位:□ 轻 □ 中 □ 重
选此档位的理由:______________________
```

**避坑**:第一次做的品类,建议先轻档摸底,别一上来选重档。

### Step 3 · 关注面聚焦(5 分钟)

即使是"全维度"覆盖,也要有一个**主聚焦**:

```
主聚焦(选 1):
□ 体验诊断  □ 设计语言推导  □ 供给侧洞察  □ 竞品对标  □ 机会挖掘

次聚焦(可选 1-2):
______________________
```

**避坑**:全维度平均用力 = 每个维度都不深入。定 1 主 2 次,后面判断资源分配的锚点。

### Step 4 · 本地素材梳理(5-10 分钟)

检查工作目录里是否已有:

```
必备:
□ 频道现状截图(京东自身)—— 路径:______
□ 竞品截图(至少 3 家)—— 路径:______

可选:
□ 已有的相关分析文档 —— 路径:______
□ 用户访谈笔记 —— 路径:______
□ KPI 数据表 —— 路径:______
□ 舆情摘录 —— 路径:______
```

**避坑**:很多人跳过这一步直接开搜,结果发现内部数据没准备好,报告 E 层写不深。

### Step 5 · 输出运行计划

把前 4 步汇总成一份**运行计划**,存在品类目录里的 `运行计划.md`:

```markdown
# {品类}行业分析 · 运行计划

**日期**:YYYY-MM-DD
**执行人**:XXX
**档位**:中档
**品类范围**:XXX(包含 / 排除)
**主聚焦**:体验诊断
**次聚焦**:设计语言推导

## 本地素材
- 频道现状截图:./频道现状/(12 张)
- 竞品截图:./竞品截图/(暂无,阶段 2 补)
- 相关文档:无

## 预计里程碑
- Day 1-2:阶段 2-3(外部调研 + 京东内诊)
- Day 3-4:阶段 4-5(验证 + 机会合成)
- Day 5-6:阶段 6-7(设计推导 + 装配)
- Day 7:内部评审

## 关注的 3 个核心问题
1. XXX
2. XXX
3. XXX
```

## AI 辅助 prompt 示例

### 帮我推荐档位

```
我要做「{品类}」品类的行业市场分析报告,背景是:{背景一句话}。
业务方期望 {N} 天内交付,主要用于 {汇报场景}。
请从「轻档 1-2 天 / 中档 1 周 / 重档 2-3 周」里推荐档位,并给出理由。
```

### 帮我明确关注面

```
我做「{品类}」的行业分析,业务需求是 {需求描述}。
基于这个需求,你觉得应该主聚焦哪个方向?
选项:体验诊断 / 设计语言推导 / 供给侧洞察 / 竞品对标 / 机会挖掘
说出 2 个候选和推荐理由。
```

### 帮我列 3 个核心问题

```
我要做「{品类}」行业分析,档位「{中档}」,主聚焦「{体验诊断}」。
请帮我列出这份报告应该回答的 3 个最核心的问题(不是宽泛的"用户是谁"这种,
而是能直接指导设计动作的问题)。
```

## 产出物

- `运行计划.md`(品类目录下)
- 头脑里对 4 个问题的清晰答案

## 三档差异

| 项 | 轻档 | 中档 | 重档 |
|---|---|---|---|
| 时长 | 5-10 分钟 | 10-15 分钟 | 20-30 分钟(建议+项目 kickoff) |
| 关注面 | 只定主聚焦 | 主+1 次 | 主+2 次+跨端 |
| 本地素材 | 必备最少即可 | 全套准备 | 含用户访谈计划 |
| kickoff | 无 | 无 | 建议召集业务方对齐 |

## 自检清单

- [ ] 品类边界明确(包含什么、排除什么)
- [ ] 档位已选定,理由清晰
- [ ] 主/次聚焦已定
- [ ] 本地素材路径已知,缺失项已标记
- [ ] 3 个核心问题已列出
- [ ] `运行计划.md` 已写入品类目录

## 常见坑

- **坑 1**:品类边界不清,后面越搜越乱。→ 先精细化定义,如"图书·教辅",而非笼统"图书"。
- **坑 2**:直接跳过澄清冲入调研。→ 花 15 分钟澄清,能省下 5 天返工。
- **坑 3**:主聚焦不定,报告像"什么都讲了但没重点"。→ 主聚焦决定资源分配,必须选 1 个。
- **坑 4**:没和业务方对齐核心问题就动手。→ 至少发一次消息确认:"这次我们要回答的 3 个问题是 XXX,你觉得对吗?"
