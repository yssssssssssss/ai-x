# 无障碍走查 · 输出骨架与模板

> 本文件是 **accessibility-review skill 自己的产出结构**，不是 wiki 正典。
> POUR 四原则的内涵、9 类控件规范、A/B/C 定级档位、对比度 / 触达区等 WCAG 阈值等正典内容**一律运行时从 `research-wiki/` 现读**（见 SKILL.md 第 2 步），不在此复制。
> 下面方括号 `[…]` 是占位槽，按本次 brief 与读到的正典、以及用户提供的真实界面素材填实。**严禁脑补界面、严禁编造"读屏朗读了 XXX"**：每条问题都要有素材里的证据；未开真机的读屏判断一律标"推断，需真机验证"。

---

## 一、直接审模式 · 输出骨架（有界面素材时，默认）

开头先用一两句交代：**评估对象 / 范围 / 素材形态（截图·原型·线上·读屏录屏·描述）/ 平台（iOS·Android·H5）/ 有无读屏实测**。

### 0. 无障碍评估结论摘要（结论先行，放最前）

```
- 总体判断：[一句话——本次范围内无障碍适配整体达标情况；有几个 A 级阻断项]
- Top 阻断 / 高危速览（先修这些）：
  - [A 级：问题 + 一句整改方向]
  - [A 级 / B 级：… ]
```

### 1. 无障碍问题清单（核心产物）

```
| # | 位置 / 证据（素材中的具体处 + 读屏实际表现） | 违反的规范（POUR 原则 + 控件类型，对到正典） | 等级(A/B/C) | 等级理由 | 分平台整改方式（Android / iOS / H5） | 复测验证点 | ⚠️标注 |
|---|---|---|---|---|---|---|---|
| 1 | [如：截图2 底部加购按钮；读屏推断朗读"按钮"无名称] | [如：可感知-标签缺失 / 按钮控件规范] | [A] | [为何这个级：直接阻断/功能受损/体验瑕疵] | [Android: contentDescription="加入购物车"；iOS: accessibilityLabel；H5: aria-label] | [TalkBack 聚焦应读"加入购物车，按钮"] | [需真机验证 / draft / 未评到，无则删] |
| 2 | … | … | … | … | … | … | |
```

> 违反的规范条目对到运行时读到的 `accessibility-adaptation.md`（原则 + 控件类型）；等级用规范自带 **A/B/C**（别在此写死档位）；整改方式抽自规范 A/B/C 表"实现方式"列，按识别到的平台给。若用户未提供读屏录音/录屏，"读屏表现"列一律写"推断"并在 ⚠️ 标"需真机验证"。

### 2. 按 POUR 原则归类小结

```
- 可感知（Perceivable）：发现 [n] 条（# …）—— [一句话共性，如"多处控件/图片缺标签与替代文本"]
- 可操作（Operable）：发现 [n] 条（# …）—— [如"焦点顺序与陷阱问题"]
- 可理解（Understandable）：…
- 可兼容（Robust）：…
（只列真有发现的；原则名称以正典为准）
```

### 3. 整改清单（可直接派给研发 —— 本 skill 的关键交付）

```
按等级 / 优先级排好的整改项，每条＝问题 + 分平台改法 + 复测验证点：

【A 级 · 必须先修（直接阻断）】
- [#1 加购按钮无标签] → Android: 加 contentDescription="加入购物车"；iOS: accessibilityLabel；H5: aria-label → 复测：读屏聚焦朗读"加入购物车，按钮"
- …
【B 级 · 高优先】
- …
【C 级 · 排期优化】
- …

修复优先级（叠加 issue-prioritization 的 P0–P3 / 快赢）：
P0：[#… 为什么最先修]   P1：[…]   P2：[…]
```

### 4. 评估范围与未评到（诚实声明覆盖边界）

```
- 本次素材覆盖：[评到了哪些页面/流程/控件类型/平台]
- 未能评到：[素材没覆盖的流程/状态(空态/错误态/加载态)/机型/平台 → 标"未评到"，不假装评过]
- 需真机 / 真人验证的疑似项：[未开真机靠推断的读屏判断 → 标"需真机验证"；需真实视障用户行为才能定论的 → 标"需真人验证"，建议接 usability-testing]
```

## 二、工具包模式 · 输出骨架（无界面素材时）

> 末尾必须**明确索要界面素材**：拿到截图 / 原型链接 / 读屏录屏后即可切到"直接审"。

### 1. 交付前 checklist

```
| # | 检查项（取自 accessibility-adaptation.md 的 8 项 checklist） | 怎么核（结合读屏） |
|---|---|---|
| 1 | [如：所有控件有可读标签] | [开读屏聚焦逐个听是否有名称] |
| …（以正典为准） | | |
```

### 2. A/B/C 评级卡

```
[A/B/C 问题定级 —— 取自 accessibility-adaptation.md 运行时现读，别写死：A 级(无标签/无焦点/焦点陷阱…直接阻断)、B 级(控件类型/状态缺失…)、C 级(焦点/朗读冗余…)；每级问题类型 + 各平台实现方式]
跨问题排序取 issue-prioritization 的 P0–P3 / RICE。
```

### 3. 读屏三遍法走查脚本

```
- 开读屏：iOS 设置-辅助功能-旁白(VoiceOver)；Android 设置-无障碍-TalkBack；先练熟基本手势
- 范围收窄：[评哪个端/版本/任务/板块；机型覆盖 iOS/Android/鸿蒙]
- 三遍法：① 视觉整体浏览(对比度/触达区/颜色唯一手段/闪烁) ② 读屏线性遍历(标签/替代文本/控件类型/状态/焦点顺序/弹窗焦点/朗读冗余) ③ 键盘手势与边界(手势冲突/空错加载态/性能) → 查漏补缺
- 独立性：多人走查先各自独立再合并(亲和图聚类去重)
（走查节奏与要点取自 accessibility-audit.md，别默写）
```

### 4. 量化阈值速查

```
[对比度 / 触达区 / 文本缩放 / 闪烁 等 WCAG 基准 —— 取自 accessibility-audit.md 运行时现读，别写死数字]
```

### 5. 记录表 + 整改汇总模板

```
- 单人记录表：| 位置/证据 | 读屏实际表现 | 违反的规范条目(原则+控件) | 等级 | 分平台整改方式 | 复测验证点 |
- 汇总：亲和图聚类去重 → 按等级(A/B/C)排序 → 整改清单(分平台改法+复测点) → 接 issue-prioritization 排期
```

### 6. 给用户的素材索要

```
要直接帮你审，请发我其一：① 关键页面/流程的截图或录屏 ② 可点原型链接 ③ 可访问的线上页面 ④ 读屏(VoiceOver/TalkBack)录音或录屏(证据最硬) ⑤ 足够具体的流程描述。并告诉我平台(iOS/Android/H5)，我好给对应的整改方式。
```

## 四、《本次运行说明》模板（固定附在最后，五部分齐全）

> 让使用者知道这份评估/工具包建立在什么之上、哪里可能不牢。逐项填实，没有的写「无」。

```
---
## 本次运行说明

**① 调用的正典**（路径 + status）
- methods/standards/accessibility-adaptation.md（status: [draft/reviewed/…]）          ← 标尺/规则(POUR/控件规范/A B C定级/checklist)，必列
- methods/toolbox/collection/accessibility-audit.md（status: […]）                     ← 走查方法/三遍法/WCAG阈值，必列
- methods/toolbox/analysis/issue-prioritization.md（status: […]）                      ← 跨问题排序/P0–P3，排整改优先级时列
- [methods/toolbox/collection/usability-testing.md / models/nielsen-heuristics.md 若读了，列全]

**② 应调用但未找到的内容**（缺的正典 / 空目录）—— 只列**经 Glob/Read 核验确实不存在或为空**的；没核验过的不要写
- 无则写「无」

**③ 走空的链接**（related 指向但**经核验确不存在**的文件）—— 核验前不要假定走空
- 无则写「无」

**④ 基于 draft（未评审）/ 推断的部分**
- [哪些标尺/阈值来自 status: draft 的正典；当前依赖多为 draft]
- [哪些读屏判断未开真机、靠界面推断，已标"需真机验证"；素材未覆盖到的流程/状态/平台]

**⑤ 反馈入口**
- 评估或工具包有问题、正典需补充，请在此反馈：http://xingyun.jd.com/codingRoot/JD_Research_Wiki/Research_Wiki/settings/issues
---
```

## 五、形态示意（仅示范"长什么样"，**勿照抄内容**——务必按真实素材重写）

> 下例是凭空编的格式演示，不是任何正典内容、不是真实评估结论，也不针对真实项目。看完格式即弃。

```
本次评估：京东 App「商详页」（截图×3，移动端 iOS，无读屏录屏），对照本库无障碍规范做读屏走查，读屏表现为推断、需真机验证。

结论摘要：范围内有 2 个 A 级阻断项（加购按钮无标签、无货弹窗焦点缺失），建议上线前必修。

| # | 位置/证据(读屏表现) | 违反的规范 | 等级 | 理由 | 分平台整改 | 复测点 | ⚠️ |
|---|---|---|---|---|---|---|---|
| 1 | 截图2 底部加购按钮，仅购物车图标(推断朗读"按钮"无名称) | 可感知-标签缺失 / 按钮规范 | A | 直接阻断——用户不知这是加购 | iOS: accessibilityLabel="加入购物车"；Android: contentDescription；H5: aria-label | 旁白聚焦读"加入购物车，按钮" | 需真机验证 |
| 2 | 截图3 无货规格弹窗，左上图片(推断未朗读"无货") | 可感知-图片承载信息未描述 / 图片规范 | B | 影响库存认知、非完全阻断 | 给图片加"无货"替代文本 | 聚焦图片应朗读含"无货" | 需真机验证 |

按 POUR：可感知 2 条（#1/#2）。整改清单：A 级先修 #1(P0)、B 级 #2(P1)。
未评到：下单/支付流程截图未提供，未评。
⚠️ 本评估基于 draft 正典、且未开真机读屏（表现为推断），关键项须真机 VoiceOver 复测、必要时接 usability-testing 请真实视障用户验证。
```

> 注意上例如何**对到具体原则 + 控件规范**、如何**按 A/B/C 给等级并说理由**、如何**给分平台整改与复测点**、如何**只基于截图证据不编造读屏朗读**、如何**诚实标"未评到 / 需真机验证"**、如何**就地标 draft**——形式照此，内容必须按真实评估对象与素材重新生成。
