# 正例

以下是 Research Screenshot Analyzer 的推荐使用方式。

## 正例 1：改版前竞品截图采集

场景：

设计师要做「公益频道」改版前竞品调研，需要对比多个 App 的公益入口、内容组织和转化路径。

正确做法：

1. 明确研究主题和竞品范围。
2. 按同一用户链路采集截图。
3. 使用 DesignPeek 上传并按 App 归档。
4. 创建「公益频道竞品分析」项目。
5. 将相关截图加入项目。
6. 执行项目级 AI 分析，获得模块归类和截图对比。
7. 人工校正模块和关键结论。
8. 将校正后的截图证据用于后续研究判断和报告整理。

产出：

- 截图素材库。
- 模块归类结果。
- 跨平台截图对比报告。
- 可沉淀到 wiki 的截图证据。

## 正例 2：设计走查证据归档

场景：

设计走查发现多个页面存在信息层级、按钮可见性或视觉噪音问题，需要保留证据并形成走查记录。

正确做法：

1. 截取问题页面。
2. 上传到 DesignPeek。
3. 给截图添加备注，说明问题位置和现象。
4. 按模块或页面类型整理。
5. 导出 HTML 报告，供评审和后续整改追踪。

产出：

- 带截图证据的走查材料。
- 可复用的问题截图归档。

## 正例 3：AI 助手调用截图分析能力

场景：

AI 助手需要处理一批用户提供的竞品截图，不希望用户手动整理文件。

正确做法：

1. 检查本地服务是否启动。
2. 通过 `POST /api/upload/image` 上传截图。
3. 通过 `GET /api/screenshots` 获取截图列表。
4. 调用 `POST /api/analyze` 做单图识别。
5. 创建项目并触发项目级分析。
6. 输出结构化结果，供后续流程继续使用。

产出：

- 机器可读的截图分析 JSON。
- 可继续编排的截图证据。
