# 反例

以下是不推荐的使用方式。

## 反例 1：只有截图，没有研究问题

错误做法：

用户上传大量截图后，直接要求工具生成完整竞品结论。

问题：

- 不知道研究目标。
- 不知道竞品选择原因。
- 不知道截图对应的用户链路。
- AI 只能做表层视觉描述，难以形成可信结论。

建议：

先明确研究目标、竞品范围和关注问题，再使用本工具采集和整理证据。

## 反例 2：把工具报告直接当最终报告

错误做法：

导出 HTML 后直接作为正式用研报告提交。

问题：

- 工具报告偏截图对比和视觉识别。
- 缺少研究目标、样本说明、方法说明、结论推导和行动建议。

建议：

将工具报告作为证据附件，补充完整研究过程、结论依据和行动建议后再形成正式报告。

## 反例 3：把竞品策略判断交给截图工具

错误做法：

看到某竞品页面结构不同，就让 Research Screenshot Analyzer 判断「我们要不要跟」。

问题：

本工具不负责判断竞品战略意图，也不负责跟进决策矩阵。

建议：

使用本工具整理截图证据，再结合业务背景、用户证据和数据指标做判断。

## 反例 4：上传敏感截图

错误做法：

将包含个人信息、订单信息、账号信息的截图直接上传并执行 AI 分析。

问题：

存在隐私和数据安全风险。

建议：

先脱敏，再上传；不确定时不要执行外部模型分析。
