# 满意度诊断 · 输出骨架与模板

> 本文件是 **analyze-satisfaction skill 自己的产出结构**，不是 wiki 正典。
> KDA 的派生重要性三层做法、四分图/Kano/AHP/SEM 公式、异动归因三阶段流程、数据标准化公式、ECT 落差法等正典内容**一律运行时从 `research-wiki/methods/.../` 与 `research-wiki/models/ect.md` 现读**（见 SKILL.md 第 2 步），不在此复制。
> 下面方括号 `[…]` 是占位槽，按本批数据与读到的正典填实。各表的列/口径**以运行时读到的正典为准**，下方列名只是形态示意。
> **只输出你本次实际走了的路线**对应的块；没走的路线不强行凑。
> **输出顺序（分层，务必遵守）**：先【发现层】——诊断结论摘要 → 路线 A/B/C 的发现，写干净、能扫读；再【依据与边界层】——数据研判小结（含算力声明）→《本次运行说明》。下面为讲清怎么填，把「数据研判小结」写在最前，但**实际输出要放到发现之后**，别让方法论/算力声明挡在结论前面（见 SKILL 北极星「分层交付」）。发现层只在真正影响某条结论时留一句轻量 ⚠️，系统性口径/算力一律下沉到文末。

## 一、路线 A — 关键驱动因素 + IPA 改进优先级

### A1 驱动权重排序

逐属性一行。**"重要性"列须标清来源**：相对权重/Shapley/回归 beta（真算）还是 相关近似（未做稳健权重）。

```
## 关键驱动因素（重要性来源：[相对权重(脚本实算) / 多元回归beta / 相关系数近似]）

| 属性 | 与总分相关系数 r | 派生重要性（[归一%/beta/r]） | 表现（满意度均值 / Top-box%） | 备注 |
|---|---|---|---|---|
| [属性名] | [r] | [权重] | [均值] | [是否基本型/属性是否互斥] |
| … | … | … | … | … |
```

> 属性高相关（多重共线性）时，原始回归 beta 不稳——按 KDA 用相对权重/Shapley；没真算就用相关系数排序并标"方向估计"。

### A2 IPA 四象限（重要性 × 表现）

```
## IPA 四象限（横轴=表现/属性满意度均值，纵轴=重要性/派生权重，均值划十字）

- 🔴 重点改进（高重要·低表现）：[属性…] ← 迭代优先排期
- 🟢 保持优势（高重要·高表现）：[属性…] ← 守住别退化
- ⚪ 次要/暂缓（低重要·低表现）：[属性…]
- 🔵 过度投入（低重要·高表现）：[属性…] ← 可抽资源

（可附文字版四象限坐标或 ASCII 草图；横纵轴划线值：表现均值=[…]，重要性均值=[…]）
```

### A3 重点改进清单

```
## 重点改进清单（按"高重要 × 低表现"排序）

1. **[属性]** ｜ 重要性 [权重] · 表现 [均值] ｜ 落在「重点改进」区
   - 为什么先改它：[高重要低表现 → 最拖后腿]
   - 为什么表现差（机制，若有 ECT/开放题/回访）：[…]
   - ⚠️ 相关≠因果：建议用 A/B 验证"改它能否真正抬升总分"
2. …
```

> 提醒：基本型属性派生重要性常被低估，别因数字低就砍基本盘（Kano 兜底）。

## 二、路线 B — 满意度异动 / 掉分归因

### B0 三道闸的判定（先排除"假异动"）

```
## 异动判断（先过四闸，再决定要不要深度归因）

- 样本量闸：本期 n=[…]，对比期 n=[…]。[达标 / 模块<20 或 系统<100 → 仅作趋势监控，不归因]
- 口径闸：本期与对比期口径[一致 / 不一致 → 分数变动可能来自换口径，先对齐]
- 显著性闸：[卡方 P=… (<0.05 显著) / 置信区间 本期[..,..] vs 对比期[..,..]：不重叠=显著 / 重叠=波动 / 轻微重叠=灰区回卡方]。结论：[显著，继续归因 / 不显著，以波动为主收尾]
- 结构因素闸：扣除用户结构变化后，[体验真实下降 X% / 实为人群结构变化贡献 Y%，非体验劣化]
```

> 不显著就明确收尾，别硬编根因。结构因素拆解的带数字算法见 b-end 场景正典。

### B1 四段叙事（异动归因正典的标准输出）

```
## 归因结论（事实 — 定位 — 根因 — 总结）

**事实**：本期 [NSS/满意度] = [x]，环比 [上期 y] [↓ z%]；显著性 [已过卡方/置信区间闸]。
**定位**：下降主要由 **[某群体]** 在 **[某模块]** 的体验恶化驱动（下钻：该群体该模块 [本期 a vs 上期 b]，跌幅最大）；趋势属 [阴跌/跳水]。
**根因**：该群体在该模块 [行为数据：响应时长↑/任务失败率↑ 若有] + 不满原因占比 [原因X 占 c%，环比 ↑d%] + 用户原声 [「[匿名原话]」]。推断与 [版本发布/故障/舆情] [时间点对齐]。
**总结**：建议产研优先优化 [模块] 的 [性能/交互]，并针对 [细节卡点] 改进。[需结合后台行为数据复核的部分标注。]
```
