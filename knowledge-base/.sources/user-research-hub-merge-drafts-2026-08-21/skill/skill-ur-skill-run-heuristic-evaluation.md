## 一、直接评模式 · 输出骨架（有界面素材时，默认）

开头先用一两句交代：**评估对象 / 范围 / 素材形态（截图·原型·线上·描述）/ 用的启发式集（默认尼尔森十大）/ 评估视角**。

### 1. 问题清单（核心产物）

```
| # | 位置 / 证据（素材中的具体处） | 违反的启发式（对到正典哪条） | 严重度(0–4) | 严重度理由(频率×影响×持续性) | 改进建议 | ⚠️标注 |
|---|---|---|---|---|---|---|
| 1 | [如：截图2 商详页顶部] | [如：H4 一致性与标准化] | [0–4] | [为何这个分] | [具体可落地的改法] | [draft/需真人验证/素材未覆盖，无则删] |
| 2 | … | … | … | … | … | |
```

> 严重度档位/口径**取自运行时读到的 `issue-prioritization.md`**（NN/g 0–4 或京东《体验问题评级标准》影响范围×严重程度→等级），别在此写死；表头"严重度(0–4)"是默认 NN/g 口径的占位，若用京东标准请改表头。违反的启发式编号/名称对到 `nielsen-heuristics.md` 的条目。

### 2. 按启发式归类小结

```
- H1 系统状态可见性：发现 [n] 条（# …）—— [一句话共性]
- H4 一致性与标准化：发现 [n] 条（# …）—— […]
- …（只列真有发现的；启发式名称以正典为准）
```

### 3. 按严重度排序 · Top 问题 · 修复优先级

```
- 灾难级(4)/主要(3) 问题（应优先修）：# …
- 修复优先级（叠加 issue-prioritization 的口径）：
  P0：[#… 为什么最先修]   P1：[…]   P2：[…]
```

### 4. 评估范围与未评到（诚实声明覆盖边界）

```
- 本次素材覆盖：[评到了哪些页面/流程]
- 未能评到：[素材没覆盖的流程/状态/机型 → 标"未评到"，不假装评过]
- 需真人验证的疑似项：[靠推断、需真实用户行为/数据才能定论的 → 列出，建议接 usability-testing]
```

## 二、工具包模式 · 输出骨架（无界面素材时）

> 末尾必须**明确索要界面素材**：拿到截图/原型链接/可访问页面后即可切到"直接评"。

### 1. 启发式检查清单

```
| # | 启发式（取自 nielsen-heuristics.md） | 核查要点（这条具体看什么） |
|---|---|---|
| 1 | [条目名] | [核查问句，取自正典内涵，别默写] |
| …（十条，以正典为准） | | |
```

### 2. 严重度评分卡

```
[严重度档位与口径 —— 取自 issue-prioritization.md 运行时现读，别写死：NN/g 0–4（档位 + 频率/影响/持续性三因素）与京东《体验问题评级标准》（影响范围×严重程度→等级）两套，按是否有影响范围数据择用]
打分方式：每位评估员对"全部已发现问题"独立打分，再取均值。
```

### 3. 评估员任务书 + 两遍法脚本

```
- 评估员：[3–5 名独立评估员；依据取自 sampling.md / heuristic-evaluation.md]
- 范围收窄：[评哪个端/版本/任务/板块；机型覆盖]
- 两遍法：第一遍整体浏览熟悉系统(不评)；第二遍逐条比对+模拟使用(含逻辑边界)；最后查漏补缺
- 独立性：互不看彼此发现，先各自独立评再合并
```

### 4. 记录表 + 汇总模板

```
- 单人记录表：| 位置/证据 | 违反的启发式 | 严重度 | 改进建议 |
- 汇总：亲和图聚类去重 → 各人严重度独立打分取均值 → 按严重度排优先级
```

### 5. 给用户的素材索要

```
要直接帮你评，请发我其一：① 关键页面/流程的截图或录屏 ② 可点原型链接 ③ 可访问的线上页面 ④ 足够具体的流程描述。
```

## 五、形态示意（仅示范"长什么样"，**勿照抄内容**——务必按真实素材重写）

> 下例是凭空编的格式演示，不是任何正典内容、不是真实评估结论，也不针对真实项目。看完格式即弃。

```
本次评估：京东 App「商详页」（截图×3，移动端 iOS），用尼尔森十大启发式，按"整体浏览→模拟使用→查漏补缺"走查。

| # | 位置/证据 | 违反的启发式 | 严重度 | 理由 | 改进建议 | ⚠️ |
|---|---|---|---|---|---|---|
| 1 | 截图2：主图"紫砂壶茶巾"，标题"紫砂壶" | H4 一致性与标准化 | 3 | 高频出现、误导购买决策、反复存在 | 主图与标题品类对齐，图文一致校验 | |
| 2 | 截图3：填完信息"登录"键仍灰、无提示 | H9 帮助识别/诊断/恢复错误 | 4 | 直接卡死主流程、用户无法自救 | 给明确报错与可点态、指明缺什么 | 需真人验证触发条件 |

按严重度：4 级 1 条(#2)、3 级 1 条(#1) → P0 修 #2、P1 修 #1。
未评到：下单/支付流程截图未提供，未评。
⚠️ 本评估基于 draft 正典（nielsen-heuristics / heuristic-evaluation 当前为 draft），结论为专家视角疑似问题，关键项建议接 usability-testing 真人验证。
```

> 注意上例如何**对到具体启发式编号**、如何**按三因素给严重度并说理由**、如何**只基于截图证据不脑补**、如何**诚实标"未评到"与"需真人验证"**、如何**就地标 draft**——形式照此，内容必须按真实评估对象与素材重新生成。
