# 设计策略案例卡模板


> 用于把 PDF、截图、汇报页、研究材料转成可检索、可复用的优秀案例卡。
> 核心原则：统一主模板，按案例类型裁剪；不为填满字段编造内容；所有判断都要能追溯到原始材料。

## 0. 录入规则

### 案例类型

| 类型 | 定义 | 必填重点 |
| --- | --- | --- |
| 完整设计策略推导 | 从背景、证据、问题、洞察推导到策略、动作、取舍或验证的完整案例 | 背景、依据、问题、推导、策略、动作、取舍、复用方法 |
| 用户分析案例 | 重点解释用户是谁、在哪里卡住、为什么卡住、如何影响任务完成 | 用户场景、用户任务、行为/反馈证据、痛点归因、设计机会 |
| 竞品分析案例 | 重点解释竞品如何组织模式、阶段、触点、规则和反馈闭环 | 竞品对象、对比维度、模式洞察、本品启发、照搬风险 |
| 设计预研案例 | 以问题探索和方案方向为主，可能没有上线结果 | 背景、现状、依据、推导、策略方向、方案表达资产 |
| 优化复盘案例 | 已上线或有结果回收，重点记录变化和效果 | 目标、改动、验证方式、结果、复盘结论 |
| 表达资产案例 | 表达方式优秀，但证据链或策略链不完整 | 表达形式、组织方式、适用场景、不可作为策略结论 |

### 录入等级

| 等级 | 录入方式 | 判断标准 |
| --- | --- | --- |
| A 完整案例 | 进入主案例库 | 至少包含背景、依据、问题、洞察、策略、动作中的 5 项，并且能形成清晰推导链 |
| B 轻量案例 | 进入分类案例库 | 某一类分析或表达特别有价值，但策略链不完整 |
| C 表达资产 | 只进入表达资产库 | 页面表达、矩阵、图表或对比方式值得参考，但不能支撑策略结论 |
| D 不录入 | 不进入案例库 | 只有截图堆叠、缺少判断，或无法说明对本品有什么启发 |

### 字段填写规则

- 原文没有的信息写“原文未体现”，不要补写成事实。
- AI 基于材料归纳的内容，需要在依据性质中标注“AI 归纳”。
- 推测性判断需要标注“待验证推测”。
- 截图型材料必须保留原图路径或页码，便于后续回看。
- 竞品类案例必须写“可借鉴点”和“照搬风险”，不能只写竞品怎么做。
- 用户类案例必须写“用户任务”和“卡点原因”，不能把业务诉求直接当用户痛点。
- 完整策略案例必须能串起“依据 -> 问题 -> 洞察 -> 策略 -> 动作”。
