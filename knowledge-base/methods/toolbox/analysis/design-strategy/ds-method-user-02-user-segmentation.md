# 用户分析 / 02 用户分层


## 目标

识别不同用户类型在目标、认知、经验、敏感点和行为路径上的差异。

## 常见分层维度

| 维度 | 示例 | 设计意义 |
| --- | --- | --- |
| 经验 | 新手、熟客、专家用户 | 判断解释深度和默认路径 |
| 意向 | 高意向、低意向、犹豫用户 | 判断利益表达和行动引导 |
| 规则敏感度 | 强规则敏感、弱规则敏感 | 判断规则前置程度 |
| 价格敏感度 | 价格敏感、权益敏感、效率敏感 | 判断信息优先级 |
| 任务频率 | 高频、低频、首次使用 | 判断学习成本和复用能力 |

## 分析模板

| 用户类型 | 核心目标 | 主要顾虑 | 关键触点 | 需要的信息 | 设计启发 |
| --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |

## 输出物

- 用户类型定义
- 用户差异对设计策略的影响
- 需要优先服务的核心用户判断

## 适用条件

- 输入包含用户、触点与已有研究材料，且研究问题与本方法的目标一致。
- 若缺少必需材料，先记录缺口，不以知识库内容替代当前事实。

## 输入

- 已确认的研究目标、范围、约束和成功标准。
- 与本方法相关的可追溯用户输入、公开来源、截图、数据或既有证据。

## 执行步骤

1. 冻结研究问题、分析对象和证据边界。
2. 按本卡片正文中的维度或模型整理输入，并逐项保留来源引用。
3. 区分观察事实、分析推断和待验证假设。
4. 形成结构化输出，检查覆盖、冲突、缺口和不可照搬边界。

## 输出

- 与正文模板一致的结构化分析结果。
- 来源引用、证据缺口、风险和后续验证项。

## 常见误用

- 把方法或案例当作当前业务事实。
- 为填满模板而编造数据、用户结论或竞品能力。
- 忽略样本、时间、场景和证据适用范围。

## 证据边界

知识库只提供方法依据。当前用户、竞品和业务事实必须来自本次用户输入或可复查证据；无法核验的内容只能标为假设或缺口。

## 验证方式

- 检查每项事实是否有来源，每项推断是否引用事实，每项建议是否给出指标或验证方法。
- 使用第二来源、反例或人工复核验证关键结论；不能验证时明确降级。
