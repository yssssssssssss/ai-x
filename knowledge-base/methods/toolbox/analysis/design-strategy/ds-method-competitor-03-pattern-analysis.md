# 竞品分析 / 03 模式分析


## 目标

从竞品做法中抽象出可复用的组织模式，而不是停留在单个页面样式。

## 模式归纳

| 模式 | 典型做法 | 适合解决的问题 | 使用条件 |
| --- | --- | --- | --- |
| 集中表达 | 把关键规则和状态聚合到主触点 | 信息分散、用户找不到重点 | 信息量可控 |
| 分阶段表达 | 按时间或任务阶段切换信息 | 阶段不清、等待不确定 | 阶段边界明确 |
| 主次分层 | 主路径保留核心动作，细节进入二级 | 感知复杂、规则过多 | 用户愿意展开 |
| 能力化承接 | 把活动包装转成稳定功能 | 玩法复用、维护成本高 | 能力可沉淀 |
| 反馈闭环 | 行动后提供确认、提醒和找回路径 | 用户不确定是否成功 | 有后续触点 |

## 分析模板

| 竞品 | 采用模式 | 关键触点 | 解决的问题 | 可借鉴点 | 不可照搬点 |
| --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |

## 输出物

- 竞品模式地图
- 可复用方法
- 与本品问题的对应关系

## 适用条件

- 输入包含竞品对象与公开证据，且研究问题与本方法的目标一致。
- 若缺少必需材料，先记录缺口，不以知识库内容替代当前事实。

## 输入

- 已确认的研究目标、范围、约束和成功标准。
- 与本方法相关的可追溯用户输入、公开来源、截图、数据或既有证据。

## 执行步骤

1. 冻结研究问题、分析对象和证据边界。
2. 按本卡片正文中的维度或模型整理输入，并逐项保留来源引用。
3. 区分观察事实、分析推断和待验证假设。
4. 形成结构化输出，检查覆盖、冲突、缺口和不可照搬边界。

## 输出

- 与正文模板一致的结构化分析结果。
- 来源引用、证据缺口、风险和后续验证项。

## 常见误用

- 把方法或案例当作当前业务事实。
- 为填满模板而编造数据、用户结论或竞品能力。
- 忽略样本、时间、场景和证据适用范围。

## 证据边界

知识库只提供方法依据。当前用户、竞品和业务事实必须来自本次用户输入或可复查证据；无法核验的内容只能标为假设或缺口。

## 验证方式

- 检查每项事实是否有来源，每项推断是否引用事实，每项建议是否给出指标或验证方法。
- 使用第二来源、反例或人工复核验证关键结论；不能验证时明确降级。
