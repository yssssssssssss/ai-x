# 用户分析 / 03 旅程任务


## 目标

按照用户完成任务的真实顺序，拆解触点、动作、信息需求、情绪变化和阻断点。

## 旅程拆解

| 阶段 | 用户目标 | 用户动作 | 关键触点 | 信息需求 | 情绪状态 | 风险 |
| --- | --- | --- | --- | --- | --- | --- |
| 发现 |  |  |  |  |  |  |
| 理解 |  |  |  |  |  |  |

| 行动 |  |  |  |  |  |  |

## 关注点

- 用户是否知道当前是什么。
- 用户是否知道下一步会发生什么。
- 用户是否能找到关键决策信息。
- 用户是否能顺畅完成动作并获得反馈。

## 输出物

- 用户旅程表
- 关键触点列表
- 信息需求和反馈需求清单

## 适用条件

- 输入包含用户、触点与已有研究材料，且研究问题与本方法的目标一致。
- 若缺少必需材料，先记录缺口，不以知识库内容替代当前事实。

## 输入

- 已确认的研究目标、范围、约束和成功标准。
- 与本方法相关的可追溯用户输入、公开来源、截图、数据或既有证据。

## 执行步骤

1. 冻结研究问题、分析对象和证据边界。
2. 按本卡片正文中的维度或模型整理输入，并逐项保留来源引用。
3. 区分观察事实、分析推断和待验证假设。
4. 形成结构化输出，检查覆盖、冲突、缺口和不可照搬边界。

## 输出

- 与正文模板一致的结构化分析结果。
- 来源引用、证据缺口、风险和后续验证项。

## 常见误用

- 把方法或案例当作当前业务事实。
- 为填满模板而编造数据、用户结论或竞品能力。
- 忽略样本、时间、场景和证据适用范围。

## 证据边界

知识库只提供方法依据。当前用户、竞品和业务事实必须来自本次用户输入或可复查证据；无法核验的内容只能标为假设或缺口。

## 验证方式

- 检查每项事实是否有来源，每项推断是否引用事实，每项建议是否给出指标或验证方法。
- 使用第二来源、反例或人工复核验证关键结论；不能验证时明确降级。
