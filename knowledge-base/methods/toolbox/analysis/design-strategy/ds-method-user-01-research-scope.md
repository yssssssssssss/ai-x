# 用户分析 / 01 分析边界


## 目标

在开始分析前，明确本次用户分析服务于哪个项目、哪类用户、哪个任务阶段和哪种设计决策。

## 需要确认

| 项目 | 说明 | 结论 |
| --- | --- | --- |
| 分析对象 | 页面、模块、链路、活动阶段或业务能力 |  |
| 核心用户 | 新用户、老用户、高意向用户、价格敏感用户等 |  |
| 使用场景 | 时间、渠道、状态、任务背景 |  |
| 用户目标 | 用户想完成什么、避免什么、确认什么 |  |
| 业务目标 | 转化、留存、履约、降本、复用等 |  |
| 设计决策 | 本次分析要支持什么方案判断 |  |

## 判断原则

- 不把所有用户混成一个平均用户。
- 不把业务目标直接写成用户痛点。
- 不在场景不清时直接进入方案判断。

## 输出物

- 用户分析边界表
- 待补充材料清单
- 初步假设与待验证问题

## 适用条件

- 输入包含用户、触点与已有研究材料，且研究问题与本方法的目标一致。
- 若缺少必需材料，先记录缺口，不以知识库内容替代当前事实。

## 输入

- 已确认的研究目标、范围、约束和成功标准。
- 与本方法相关的可追溯用户输入、公开来源、截图、数据或既有证据。

## 执行步骤

1. 冻结研究问题、分析对象和证据边界。
2. 按本卡片正文中的维度或模型整理输入，并逐项保留来源引用。
3. 区分观察事实、分析推断和待验证假设。
4. 形成结构化输出，检查覆盖、冲突、缺口和不可照搬边界。

## 输出

- 与正文模板一致的结构化分析结果。
- 来源引用、证据缺口、风险和后续验证项。

## 常见误用

- 把方法或案例当作当前业务事实。
- 为填满模板而编造数据、用户结论或竞品能力。
- 忽略样本、时间、场景和证据适用范围。

## 证据边界

知识库只提供方法依据。当前用户、竞品和业务事实必须来自本次用户输入或可复查证据；无法核验的内容只能标为假设或缺口。

## 验证方式

- 检查每项事实是否有来源，每项推断是否引用事实，每项建议是否给出指标或验证方法。
- 使用第二来源、反例或人工复核验证关键结论；不能验证时明确降级。
