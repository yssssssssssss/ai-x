# 竞品分析 / 02 对比维度


## 目标

建立稳定的对比口径，让竞品分析从“截图罗列”转向“模式判断”。

## 常用维度

| 维度 | 关注问题 | 输出 |
| --- | --- | --- |
| 模式 | 竞品如何组织玩法、入口和能力 | 模式差异 |
| 阶段 | 如何表达前置、进行、等待、结束 | 阶段表达方式 |
| 信息位置 | 关键信息出现在什么页面、流程节点或反馈位置 | 信息组织方式 |
| 规则 | 复杂规则如何前置、合并、下沉或解释 | 规则策略 |
| 反馈 | 行动后如何确认、提醒、回访 | 反馈闭环 |
| 维护 | 是否降低运营配置和异常场景成本 | 维护启发 |

## 输出物

- 对比维度表
- 截图和证据索引
- 初步设计启发

## 适用条件

- 输入包含竞品对象与公开证据，且研究问题与本方法的目标一致。
- 若缺少必需材料，先记录缺口，不以知识库内容替代当前事实。

## 输入

- 已确认的研究目标、范围、约束和成功标准。
- 与本方法相关的可追溯用户输入、公开来源、截图、数据或既有证据。

## 执行步骤

1. 冻结研究问题、分析对象和证据边界。
2. 按本卡片正文中的维度或模型整理输入，并逐项保留来源引用。
3. 区分观察事实、分析推断和待验证假设。
4. 形成结构化输出，检查覆盖、冲突、缺口和不可照搬边界。

## 输出

- 与正文模板一致的结构化分析结果。
- 来源引用、证据缺口、风险和后续验证项。

## 常见误用

- 把方法或案例当作当前业务事实。
- 为填满模板而编造数据、用户结论或竞品能力。
- 忽略样本、时间、场景和证据适用范围。

## 证据边界

知识库只提供方法依据。当前用户、竞品和业务事实必须来自本次用户输入或可复查证据；无法核验的内容只能标为假设或缺口。

## 验证方式

- 检查每项事实是否有来源，每项推断是否引用事实，每项建议是否给出指标或验证方法。
- 使用第二来源、反例或人工复核验证关键结论；不能验证时明确降级。
