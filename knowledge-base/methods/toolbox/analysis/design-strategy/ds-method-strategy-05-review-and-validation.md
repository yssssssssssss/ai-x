# 设计策略 / 05 评审验证


## 目标

让设计策略可以被评审、被决策、被上线后验证。

## 汇报结构

| 部分 | 说明 |
| --- | --- |
| 背景 | 项目为什么重要，覆盖哪些用户和业务场景 |
| 问题 | 用用户、竞品、业务、数据证据说明现状问题 |
| 归因 | 收敛 2 到 4 个高阶问题 |
| 策略 | 说明每个问题对应的策略层 |
| 动作 | 展示触点级设计措施 |
| 价值 | 对应用户收益、业务收益和验证指标 |
| 决策 | 说明需要评审确认的规则、优先级、取舍和风险 |

## 验证模板

| 策略目标 | 过程指标 | 结果指标 | 观察周期 | 风险预案 |
| --- | --- | --- | --- | --- |
| 降低认知混乱 | 关键说明点击率、规则展开率 | 咨询量、误解反馈 |  |  |
| 降低感知复杂 | 关键触点点击率、停留时长 | 转化率、流失率 |  |  |
| 打通路径阻断 | 任务完成率、回访率 | 加购率、预约成功率 |  |  |
| 降低维护成本 | 配置项数量、异常场景数量 | 运营修改次数、复用率 |  |  |

## 输出物

- 评审叙事
- 决策问题清单
- 上线验证计划
