# Agent API

## 目的

提供认证、任务、媒体、反馈、Skill 列表和拓扑可视化的 HTTP/SSE 入口。

## 模块概述

- **职责:** 认证与 owner 隔离、请求解析、编排器调用、响应和 SSE 进度转发。
- **状态:** 🚧开发中。
- **最后更新:** 2026-07-23

## 规范

### 需求: 任务资源隔离
**模块:** Agent API

除公开接口外，所有任务操作必须校验 JWT，并将不属于当前用户的任务作为不存在处理。

#### 场景: 访问其他用户任务
- 请求通过认证但任务 owner 不匹配。
- 返回 `404`，不泄露任务是否存在、计划、媒体、执行日志或报告。

### 需求: 可操作的执行错误
**模块:** Agent API

API 必须将用户可修复问题、状态冲突和上游依赖失败用稳定状态码区分。

#### 场景: 重复提交执行请求
- 首次请求领取任务后，后续请求返回 `409`。
- 前端不盲目重试，不再次调用 Tool 或 Skill。
- 缺少或不合法媒体返回 `422`；上游超时或不可用返回 `504` 或 `502`。
- 非流式响应与 SSE `error` 事件均携带稳定的 `code` 和 `message`，并保留 `error` 兼容字段。

### 需求: 可测试 HTTP 入口与反馈汇总
**模块:** Agent API

应用构建与端口监听分离：`createApp()` 仅装配中间件与路由，`startServer()` 保留开发启动行为。Node 原生 HTTP 集成测试覆盖 JWT、媒体前置条件、状态冲突、并发领取和反馈汇总。

#### 场景: 查看个人反馈指标
- 已认证用户请求 `GET /api/tasks/feedback/summary`。
- 仅聚合该用户拥有任务的评分、采纳率和评论数量。
- 响应不包含评论正文，并以 `commentsRedacted: true` 明示脱敏边界。

## 注意事项

- 拓扑接口的匿名访问边界需在 P2 明确。
