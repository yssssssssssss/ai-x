# 阶段 8 · 报告装配与自检

> 前 7 阶段的产出散在多个文档,本阶段把它们装成一份最终报告,并跑自检清单确保交付质量。

## 目标

- 复制对应档位的模板到品类目录
- 把前 7 阶段的产出**按 10 维度 + 品类差异资产归位**填充模板
- 补齐 H(可衡量指标)、I(方法论)两个"临门一脚"章节
- 走完自检清单,确保没漏
- 产出 1 份 `.md`(内容底稿)→ 渲染成 1 份 **HTML 汇报页**(最终交付物)

> **交付形态**:`.md` 是内容底稿(改起来快、便于自检),**最终交付是一份自包含的 HTML 汇报页**——**5 Tab 分类(行业洞察 / 品类差异资产 / 竞品分析 / 体验诊断 / 设计策略)** + 固定头部 + Tab 内侧边栏,浏览器打开即可汇报。规范见本阶段末尾「HTML 汇报页输出规范」。**先用 .md 跑完内容、过完自检,再渲染 HTML**——内容与形式解耦,返工最少。
>
> **⚠️ 协作模式例外(不锁 HTML)**:以上 5 Tab HTML 骨架是"**我们独立出报告**"时的硬约束。但当我们作为"行业专家"和更专业的**竞品分析/体验诊断 skill 拼一份联合产出**时,进入**协作模式**——**只交「行业洞察 + 品类差异资产」两块的结构化内容(`.md`/JSON 片段),格式服从主编译方,不强推 5 Tab HTML**(否则和别人的结构打架、破坏联合产出物)。判断:是"我们主导的独立报告"→走5 Tab HTML;是"给别人拼的模块"→交内容、不锁格式。

> **⭐ 装配前:高风险章节先交提纲预审(借鉴投行行研,防整章返工)**。中/重档报告里,**市场规模、竞品分析、设计策略**这三章最容易方向跑偏(数字口径错、竞品分组逻辑不对、机会优先级拍脑袋)——一旦写完整章才发现方向错,返工成本极高。所以**装配这三章的正文前,先给用户一个 6-10 行提纲**(要回答的核心问题 / 数据口径或竞品分组逻辑 / 关键假设 / 打算怎么呈现),用户点头再展开写。低风险章节(行业趋势/供给/体验现状)直接写完给用户抽检即可,不必预审。
> - 轻档 / 第0档:跳过预审,别为流程增负担。
> - 提纲预审 ≠ 多一轮完整评审:只花用户 1 分钟扫一眼方向,省的是整章重写。这一步是"可选增强",用户嫌繁可跳,但市场规模/竞品这种硬骨头强烈建议做。

### Step 5 · 写摘要 & TL;DR(最后写)

摘要放报告最前面,是决策者唯一保证读的部分:

```markdown
# {品类}行业市场分析 · {档位}

**版本**:v1.0 · YYYY-MM-DD
**执行人**:XXX
**档位**:中档
**主聚焦**:体验诊断

## TL;DR

- **一句话结论**:"{品类}频道当前的核心问题不是 XX,而是 XX。"
- **3 大发现**:
  1. {发现 1,含关键数字}
  2. {发现 2,含关键数字}
  3. {发现 3,含关键数字}
- **推荐 3 大动作**(短期):
  1. {动作 1}
  2. {动作 2}
  3. {动作 3}
- **成功指标**:{主指标目标}
```

TL;DR 的写作原则:
- 500 字以内
- 有 1 个"一句话结论"
- 3 大发现要有数字
- 3 大动作要具体、可执行
- 主指标要能落到数字上

### Step 6 · 每章补一句话结论

在每大章末尾用引号包围的一句话浓缩:

> "图书频道当前需要做的不是加入内容,而是让决策链路不被打断。"

好的一句话结论有 3 个特征:
- 短(不超过 30 字)
- 有对比("不是 X,而是 Y")
- 可直接被汇报引用

## HTML 汇报页输出规范

> `.md` 自检通过后,渲染成一份**自包含的 HTML 汇报页**作为最终交付。设计目标:决策层不点任何 Tab 就看到结论,想深挖再按"懂行(洞察+差异资产)→ 对标 → 问题 → 方案"的顺序逐 Tab 展开。

### 核心区分:什么固化、什么按品类自定义

这套规范的关键是**骨架统一、配色统一,只字体/母题按品类微调**——每个品类的报告结构、阅读体验、色彩系统都一致(现代、清新、易读、好维护),辨识度靠品类专属的内容深度和少量字体/图案点缀来体现,**不再靠换配色**。

> **⚠️ 2026-07 起的重要变更**:配色从"按品类心智生长"改为**全品类统一的清新配色 token**。原因:各品类自定义配色导致报告观感不一、有的偏暗偏花、可读性参差;统一成"白卡 + 冷灰底 + 蓝橙紫功能色"后,任何品类的报告都现代、清新、一眼可辨同源。品类特色改由"内容 know-how + 字体/母题微调"承载,不再由配色承载。

**✅ 必须固化(所有品类的报告都一样):**

| 固化项 | 规则 |
|---|---|
| **页面结构** | 固定头部(含 TL;DR)+ **5 Tab(行业洞察/品类差异资产/竞品分析/体验诊断/设计策略)** + 每个 Tab 内按章节维度做锚点定位。**正文占满核心宽度,章节侧边栏浮在核心区左外侧留白**。见下方结构图。**禁止改成长滚动页**——骨架是所有品类统一的,不可动。 |
| **核心内容宽度** | 头部、Tab、正文核心区统一同一 `max-width`(约 1016px)、左右对齐。**正文独占这个宽度,不再与侧边栏分栏**——章节侧边栏移到核心区**左外侧的留白区**(sticky 跟随滚动);视口不够宽(约 <1240px)时,侧边栏收回核心区顶部横向排列。 |
| **5 Tab 章节归类** | A/B/C/J→行业洞察,D→竞品分析,E→体验诊断,F/H→设计策略,**G(设计语言)+ 品类差异资产五段→品类差异资产 Tab**(见下方映射表),不随品类变。 |
| **🎨 配色系统(统一清新配色,不再按品类变)** | **全品类共用同一套 token**(见下方「统一配色 token」)。核心:**卡片/模块用纯白 `#ffffff`,页面底冷浅灰 `#f5f6f9`,内嵌小块 `#f6f7f9`,分隔线 `#edeef2`**;文字三档 `#1b1c1f / #5f6672 / #9aa0ab`;**功能色一 Tab 一色**——行业洞察=蓝、体验诊断=橙、设计策略=紫、京东哲学=红、流程/中性=灰、辅助=绿,每色配一个极浅底色。低饱和、清新、现代。 |
| **头部层级** | 头部各模块(kicker 标签 / 大标题 / 副文案 / 档位标签 / TL;DR / Tab 栏)用**间距 + 细分隔线**区分层级,**不用卡片式边框+阴影+圆角**——保持轻、聚焦内容,不让"外壳"抢戏。具体:①**kicker**(顶部小标签"垂类行业市场分析·档位·品类")用**纯文字**、无圆点无胶囊底、**左对齐顶头**与大标题左边缘齐;②**大标题**要够大够醒目(H1 ~40px);③**副文案/正文不另设窄 `max-width`**,占满核心宽度(与档位标签、TL;DR、章节卡右边缘对齐);**副文案要精简克制**——一句话点出"这份报告是什么"即可(如"一份 X 频道的行业诊断与设计策略,并沉淀出可复用的 X 品类差异资产"),**不要用破折号再展开解释"具体怎么做/为什么"**,那些留给正文,标题区只做提纲挈领。 |
| **TL;DR 模块** | TL;DR 是一个**独立成型的总述模块**,不是散点:一句话结论(醒目、可加浅底或直接置于冷灰底)+ 下方"核心发现/差异化定位/首要动作"**三张独立白卡并排**(不是三段飘着的文字)。整块与头部/章节**同一核心宽度对齐**(`1016px + 32px 内边距`,别用整块白底撑满 1016 导致比章节宽出一截)。**每张卡竖向布局:顶部一个 44px 圆角方块(圆角~12px)装 emoji 图标(~22px 居中)→ 标题(~15px 加粗)→ 正文**;三张卡的图标块底色分别用功能色的极浅底(发现=`--insight-soft` 蓝 / 定位=`--diagnose-soft` 橙 / 动作=`--strategy-soft` 紫),emoji 建议 🔍发现 / 🎯定位 / 🚀动作。是否加"TL;DR"字样标签可选。 |
| **Tab 交互与视觉** | 选中态用**底部下划线**(文字变深加粗 + 2px 下划线 + 序号点缀),**不用重色块/深底胶囊填充**;Tab 底线**限定在核心宽度内,不贯通整屏**;Tab 栏 `position:sticky; top:0` **吸顶**。**切 Tab 的滚动行为按"是否已吸顶"分两支**(关键,产 HTML 必须落实):①**未吸顶**(还能看到头部/TL;DR,`tabNav.getBoundingClientRect().top>0`)→ 切后 `scrollTo({top:0})` 平滑回顶,让用户看到完整头部;②**已吸顶**(Tab 已贴顶,`top<=0`)→ **不回顶、不跳动**,用 `scrollBy` 把新 panel 第一个 `.chapter` 顶端微调到紧贴 Tab 栏下沿(`chapTop - navBottom`),做到"原地无缝换内容"。**别只写"保持滚动位置"**——那样已吸顶时新内容可能起始位置错乱;必须做这个吸顶感知的对齐。 |
| **质感** | **白色大卡片(章节卡/TL;DR)一律不描边、不阴影,只留大圆角(~16-18px)**——层次全靠"白卡 vs 冷灰底"的底色差拉开,不靠边框和重阴影。卡内的内嵌小块(说明块/表格/机会卡等)用冷灰底 `--soft`;**强调/高亮块(如"可借鉴点""设计动作")跟随同一灰底即可,不额外用彩色底强化**——统一克制,避免"花"。**Tab 栏与上方 TL;DR 之间留足间距**(Tab 是 sticky,`margin-top` 给到 ~40px+),别贴太近。 |
| **哲学呈现方式** | 头部哲学标识 + 诊断挂原则标签 + 定位标价值观,贯穿方式固定。 |
| **排版与层级(现代基线)** | **用"文字级差 + 留白"做信息层级,不用装饰件,层级靠字号/字重/间距区分**:①标题前**不加圆点**、小标题前**不加竖条**(那是旧样式);②段落强调块**不加左竖线**,改用浅底色块或纯加粗;③正文行距宽松(`line-height:1.85-1.9`)、段距充足(段间 `15px+`、章节内边距 `32px+`),报告文字多,要留呼吸感;④英文副标题/正文与中文标题**左对齐**,不留"为对齐圆点而设的缩进";⑤**字阶要收敛,别碎**——正文级(正文/表格/说明块/卡片正文)统一到**同一档**(如 13.5-14px),标签/微标另设 1-2 档即可,**同屏 4 档以上正文级字号 = "花",必须并档**;别给每个小组件单设字号;⑥**加粗要克制**——一段里`<strong>`别超过 1-2 处,满屏加粗等于没有重点,反而显花;多点强调改用"小标题引导句 + 正文"的结构;⑦**并列多项要分行**——凡"①…②…③…"每项都是一句以上完整论述的,**每项独立成行**(`<br>` 或 `<li>`),领起的标题句单独一行;只有一句话内的短枚举(如"① A ② B ③ C"排序)才可内联。**这条对正文段落、灰底 note/说明块、卡片正文一视同仁**——note/说明块里的 ①② 也常挤成一坨,同样要拆行。 |

### 5 Tab 的章节归类(固定映射,10 维度 + 资产库各归其位)

> Tab 命名与顺序对齐本工作流定位:**行业洞察 / 品类差异资产 / 竞品分析 / 体验诊断 / 设计策略**。
> **⚠️ 2026-07 顺序调整(战略级)**:品类差异资产从第 5 位**提到第 2 位**,紧跟行业洞察。原因:**我们的护城河是"垂类行业专家"**——「行业洞察」(这个品类怎么运转)+「品类差异资产」(基于同一份品类理解,这个品类该长什么样)是同源的两块,共同构成"我们比别人更懂这个垂类"的名片,应当**前置、着重展示**。而竞品分析、体验诊断、设计策略是"针对京东具体现状的分析",别的团队也在做、甚至有更专业的 skill。这样编排:**先证明我们懂行(洞察+差异资产)→ 再看针对京东的落地分析(竞品/诊断/策略)**;与别的团队的 skill 编译组合时,前两块是我们的独特贡献,后三块可由更专业的 skill 补位。

| Tab | 装的报告章节(维度) | 叙事角色 |
|---|---|---|
| **① 行业洞察** | 行业趋势(A)· 用户洞察(B)· 供给侧(C)· 商业与经营逻辑(J)· **【附注区】升档指引 + 方法论与数据说明(I)** | 我们懂行(一):这个行业怎么运转、怎么赚钱;末尾附"报告能用到什么程度 + 怎么做的" |
| **② 品类差异资产** | 设计语言推导(G,作推导起点)+ 五段资产(心智锚点/视觉基因/文案语气/玩法基因/动效性格) | 我们懂行(二):基于品类理解,这个品类该长什么样、说什么话、玩什么、怎么动——垂类专家的差异化主张。**注:渲染成 HTML 时段标题直接用文字(心智锚点/视觉基因/…),不加 ①②③ 序号**(序号只在方法论文档里指代用) |
| **③ 竞品分析** | 竞品与参考(D)——6 板块(选样/四要素总览/商业对比/体验对比/心智象限/采集清单) | 对标:别人占了什么位、空白在哪 |
| **④ 体验诊断** | 京东内部诊断(E)——三章:①现状概览 ②四类问题(每条挂钩6原则 + 品类特异性,去泛化)③诊断→原则命中统计(哪条原则命中多/严重) | 问题:京东频道卡在哪、违反了哪条平台原则、最该先修哪条 |
| **⑤ 设计策略** | 机会与策略(F)· KPI 假设(H)· 设计语言一句话结论(指向品类差异资产) | 方案:该做什么、投入产出 |

> **Tab 顺序即汇报叙事线(新)**:行业洞察(懂行·背景)→ 品类差异资产(懂行·主张)→ 竞品分析(对标)→ 体验诊断(问题)→ 设计策略(方案)。前两块是"垂类专家名片"(我们的优势,着重看),后三块是"针对京东的落地分析"(可看我们的,也可与更专业的竞品/诊断 skill 组合)。
> **设计语言(G)的位置 + 色板不重复**:「品类差异资产」Tab 开头放**设计语言推导链**(属性→气质→主推方向 + 一句话结论)作推导起点,**只讲方向、不列具体色值**;**完整色板(带 hex + 继承/增量)只在「视觉基因」段给一次**(色板的唯一权威位置),推导链末尾一句"具体色板见视觉基因"指过去即可,别两处都列色值。「设计策略」Tab 只留一句话结论 + 指向品类差异资产,避免重复。**注意:品类差异资产已前置到第 2 位,不再依赖"读完设计策略再看沉淀"的顺序**——它是独立的品类主张,自身成立,不是策略的附属结论。
> **升档指引 + 方法论(I)的位置(固定)**:两块都放**「行业洞察」Tab 末尾的「附注区」**,不放页脚、不放设计策略 Tab、不单独占 Tab——它们是"关于这份报告本身"的说明(能用到什么程度、怎么做的、数据边界),归在开篇背景 Tab 收口最自然。**附注区上方用一条「双细线 + 居中淡标题(如『附 · 报告说明』)」的分割**,与正式行业洞察章节轻轻隔开;侧边栏锚点照常列出这两项。
> **档位无关**:轻/中/重档章节数不同,但都落进这五类,同一套 HTML 模板通吃。

### 侧边栏规则

- 顶部横向 Tab 切大类;左侧竖向锚点跳章节。
- **侧边栏锚点徽标在每个 Tab 内用连贯序号 A/B/C/D…**(每个 Tab 独立从 A 起),**不要重复、不要跳字**——别用维度代号(会出现 t2 全是 D、t4 全是 F 这种重复,或 A/B/C/J 跳字)。序号只表"本 Tab 第几节",纯导航用途。
- **侧边栏浮在核心区的左外侧留白区**(`position:sticky` 跟随滚动),不挤占正文——正文独占核心宽度。视口 <1240px 容不下时,侧边栏收回核心区顶部横向排列。
- 侧边栏**只显示当前 Tab 下的章节**,切 Tab 时侧边栏内容跟着换;页面滚动按上面「Tab 交互」的吸顶两分支处理(未吸顶回顶、已吸顶原地无缝对齐),不是简单"保持位置"。
- 每个 Tab 下的章节都要能被侧边栏锚点单独跳转——**多小节的 Tab 要拆成多个带 id 的 `section`**,不要把几块塞进一个 section(否则侧边栏只有一个锚点)。例:竞品分析 Tab 拆成 选样分组 / 四要素 / 心智象限 三个 section。
- 「行业洞察」装 A/B/C/J 四章 + 附注区(升档指引/方法论);「品类差异资产」列设计语言推导+五段(心智/视觉基因/文案/玩法/动效);「竞品分析」列 6 板块(轻档为选样/四要素/心智象限);「体验诊断」列三章(现状概览/四类问题/原则命中统计);「设计策略」列机会/行动方案/设计/KPI。

### Tab 切换 · 参考实现(产 HTML 直接照抄这段逻辑)

> 关键是**吸顶感知**:未吸顶回顶看头部、已吸顶原地无缝换内容。别只写 `preventDefault` 或简单保持滚动位置。

```js
var tabNav = document.querySelector('.tab-nav');   // sticky top:0 的 Tab 栏
document.querySelectorAll('.tab-btn').forEach(function(b){
  b.addEventListener('click', function(){
    var t = b.getAttribute('data-target');
    var stuck = tabNav.getBoundingClientRect().top <= 0;  // 是否已吸顶
    // 切激活态 + 切 panel
    document.querySelectorAll('.tab-btn').forEach(x=>x.classList.toggle('active', x===b));
    document.querySelectorAll('.tab-panel').forEach(p=>p.classList.toggle('active', p.getAttribute('data-panel')===t));
    renderSide(t);                                   // 侧边栏换成当前 Tab 的锚点
    if (stuck) {                                     // 已吸顶:新 panel 首章节紧贴 Tab 栏下沿,原地无缝
      var firstChap = document.querySelector('.tab-panel.active .chapter');
      if (firstChap) {
        var delta = firstChap.getBoundingClientRect().top - tabNav.getBoundingClientRect().bottom;
        window.scrollBy({top: delta, behavior:'auto'});
      }
    } else {                                         // 未吸顶:平滑回顶,露出完整头部
      window.scrollTo({top:0, behavior:'smooth'});
    }
    setTimeout(highlight, 60);                        // 刷新侧边栏当前锚点高亮
  });
});
```
> `renderSide(t)` 按 nav map 渲染当前 Tab 的锚点(连贯 A/B/C);`highlight()` 按滚动位置高亮当前章节锚点。切 Tab **不改 URL hash、不触发页面重载**。

### 图表可视化建议(能图则图,不堆表格)

> 报告默认是"表格 + 数字卡"。想让关键数据从表格里站出来,用 **lieflat-chart**(单色数据可视化 skill,已用户级安装于 `~/.claude/skills/lieflat-chart`)出图,嵌进对应章节。它和本报告审美同源(白底/克制/编辑感),融合度高。**没装或想快速出图,退回本表右列的"纯 CSS/SVG 兜底形式"也可以。**

| 内容 | 数据形状 | lieflat 推荐图型 | 纯 CSS/SVG 兜底 |
|---|---|---|---|
| 机会四维打分(F) | 少类目排名(≤8) | **F5 Tick Rows**(横向 tick,1 tick=1 分) | 分组条形 |
| 金选好评率 / 单一占比(E) | 一个百分比 | **L14 Hundred Field**(百点网格,1 点=1%) | 数字卡 |
| 四类问题 / 100% 构成(E/F) | 占比分段 | **F4 Tick Donut**(环形表盘,1 tick=1%) | 占比环图 |
| 市场规模/增速(A) | 时间序列 | **F2 Hairline Line / F3 Hairline Area** | 折线/柱状 |
| 竞品心智定位(D) | 二维象限 | (报告已有 `.quad` 象限,够用) | 二维象限图 |
| 商业逻辑→设计含义(J) | 左右对照 | (用表格) | 左右对照 |
| 三档优先级(F) | 分期泳道 | (用报告已有 `.timeline`) | 时间线泳道 |

> **⚠️ 手写 CSS/SVG 图表的铁律**(兜底图不走 lieflat 时也必须守):
> - **只用黑/灰阶 + 至多一个强调色,别用红蓝橙紫花色**——图表要融进"白卡+冷灰底"的克制调性。语义靠"深浅"表达(如严重度:深炭灰=高、中灰=中、虚线空框=无),不靠彩虹色。
> - **每个数据图必带一句图例说明编码逻辑**(如"柱长=命中问题数,深浅=严重度"),否则读者会误读"为什么这条更长"。
> - **视觉落差要对应真实数据差、且不突兀**:柱长按数值成比例,但避免"满格 vs 极短"的突兀跳变(如命中2→100%、命中1→60%,而非 100% vs 一小截)。
> - **别让缺 CSS 的元素塌成怪样子**:手写图型(如 conic-gradient 环形、柱状)务必把宽高/圆角/尺寸写全,漏了会塌成一条丑色带(踩过)。渲染后务必肉眼验一遍。

#### 用 lieflat 出图的 4 步(实战验证过)

1. **调用 skill**:`/lieflat-chart`(或直接说"用 lieflat-chart 把这组数据画成图")。它会按"数据形状→选图型"的硬约束走,不用你指定图型名。
2. **⚠️ 只用纯 SVG 图型(Lupi Editorial / Lupi Basics),避开 Glance**。原因:Glance 和交互大图依赖 ECharts/Chart.js 的 **CDN**,一旦用了,报告就**违反"自包含单文件、离线可开"**(见本阶段技术约束 + 坑 7)。选型时明确告诉它"要纯 SVG、离线可用"。
3. **让它产"嵌入版"而非"独立单文件"**:图的墨色/边框/标签复用报告自己的 CSS 变量(`--ink` / `--border` / `--panel`),SVG 片段 + 渲染 JS 用 IIFE 包裹内联进报告,和报告已有脚本零命名冲突。
4. **保留原表格,图作增强**:在表格**下方**加 `<figure>`,不删表。断网/打印/读屏场景下数据仍在表里。

#### 两个必须处理的技术细节(踩过坑)

- **Tab 内的图要延迟渲染**:图在非默认 Tab 里时 `display:none`,SVG 没尺寸、IntersectionObserver 不触发 → 改成**切到该 Tab 才渲染**(只渲一次,用 `dataset.done` 去重),并加 `window.addEventListener('beforeprint', …)` 钩子,打印/导 PDF 前强制画全部图。
- **入场动画 + 打印**:lieflat 图默认淡入动画;务必内置 `@media (prefers-reduced-motion:reduce){animation:none}`,否则打印/截图那一刻图会偏淡甚至空白。

> 参考实战成品:`品类测试/京东宠物行业分析/图表输出/`(三种图型的嵌入版)+ 已把三图嵌入 `京东宠物行业洞察.html`(机会打分 tick / 金选百点 / 四类问题环形)。
> 图表配色遵循平台设计系统 token;lieflat 本身是单色(纸灰+炭黑),天然符合【精巧克制】。若手写兜底图,用中性色 + 单一强调色,别自造花哨配色。

### 设计动作线框图规范(阶段5 行动方案的④设计动作)

每条设计师行动方案的「④设计动作」必须配**一张灰阶低保真线框图**(纯 HTML/CSS 画,非流程图):
- **手机框示意**:一个手机外框内画关键界面布局(顶部导航条 + 内容块),表达设计动作的布局意图;
- **灰阶三级**:深灰(`#4a4a4a` 级)=按钮/强调,中灰(`#d6d6d6` 级)=图片/模块占位,浅灰(`#e8e8e8` 级)=文字/次要占位;
- **标注**:图下标"低保真线框 · 灰阶示意(落地配色见资产库色板)"——线框聚焦布局、不聚焦配色;
- **目的**:比 ASCII 文字框"显象",设计师一眼看懂布局意图,又不越俎代庖画成视觉稿。

### 截图内嵌规范(竞品亮点截图 + 页面现状/诊断截图)

报告里有两类真实截图,**压缩与内嵌方式相同,展示方式不同**。

**共同的压缩铁律(踩过坑,务必按宽缩放)**:
- **一律按"宽度"缩放,禁用 `-Z`(最长边)**——手机截图常是 375×3000+ 的超长图,`sips -Z 600` 会按最长边缩,结果**宽度被压到几十 px、糊成一团**(踩过)。正确:`sips --resampleWidth 400 -s format jpeg -s formatOptions 80 原图.PNG --out out.jpg`(展示框约 200px 时,给 400px 宽=2 倍像素,清晰);超长图可降到 `--resampleWidth 340` + 质量 76 控体积。
- **Base64 内嵌**:`data:image/jpeg;base64,...` 进 `<img>`,保持自包含单文件(相对路径会在移动/外发时图裂)。
- **体积**:单张几十~几百 KB;整份 HTML 含多图到 1MB+ 可接受(清晰优先),但别用无必要的高质量。

**A. 竞品亮点截图**(阶段2 模块级拆解):**缩略图(~150px 宽)+ 点击放大**(复用 `.modal` 放大层,`cursor:zoom-in`)。每家竞品嵌 1 张最有代表性的即可。拿不到的(需登录等)不硬凑,标〔判〕。

**B. 页面现状/诊断截图**(阶段3 体验诊断的四类问题、频道现状):**用"手机屏比例框"展示,不做点击放大**。
- 每张图放进一个 **375×812 比例的框**(`aspect-ratio:375/812`,宽约 200px),图 `width:100%`;内容长的图在框内 **`overflow-y:auto` 上下滚动**,只露首屏——像在真机上看。
- **一类问题可并排多张**(如"心智错配"配签到+答题两张),flex 横向排列。
- **不绑点击放大**(用独立类如 `.pframe`,别复用竞品的 `.shot`,放大 JS 只绑 `.shot img`)——页面截图看的是"首屏氛围/信息密度",框内滚动已够,放大反而干扰。
- 诊断截图的价值是**给"图书特异性"判断配眼见为实的锚点**(如"首页信息堆叠"配首页截图),每张配一句话说明它对应哪条问题。

### 技术约束

- **自包含单文件**:CSS 内联、图表用轻量内联 SVG 或纯 CSS 实现,不依赖外网 CDN——双击即开,可离线汇报、可直接发给他人。
- **图片一律 Base64 内嵌**(竞品截图等),不用相对路径——保证 HTML 移动/外发/离线都不图裂。内嵌前先压缩缩略图控制体积(见上)。
- 响应式:优先保证笔记本投屏(1280px+)清晰;移动端可读即可。

## 常见坑

- **坑 1**:TL;DR 变成"目录导读" → 应是"结论摘要"。看完不用翻正文就能拿去汇报。
- **坑 2**:每章一句话结论写成套话("总的来说……很重要") → 必须包含对比或指向动作。
- **坑 3**:KPI 目标写"提升"或"优化" → 必须是具体百分比或数值,即使是假设值。
- **坑 4**:附录 I 简单写"参考了行业报告" → 每个数据源要写清:报告名、发布方、发布日期、URL(如有)。
- **坑 5**:装完报告没读一遍 → 至少通读 2 遍,一次找逻辑漏洞,一次找错别字和格式。
- **坑 6**:内容还没定就先渲染 HTML → 先用 .md 跑完内容、过完自检,内容锁定后再渲染 HTML,否则改内容 HTML 也得返工。
- **坑 7**:HTML 用了外网 CDN 的图表库/字体 → 换个没网的会议室就打不开。**必须自包含单文件**,离线可开。
- **坑 8**:用 lieflat 出图时选了 Glance 或交互大图 → 它们依赖 ECharts/Chart.js 的 **CDN**,直接违反坑 7。**只用 Lupi Editorial / Lupi Basics 的纯 SVG 图型**,选型时明说"要离线可用"。
- **坑 9**:图放进 Tab 后不显示 → Tab 面板 `display:none` 时 SVG 没尺寸、观察器不触发。改成**切到该 Tab 才渲染**(dataset 去重)+ `beforeprint` 兜底,别指望页面一加载就画好。
- **坑 10(旧样式惯性 + "花"的四个成因)**:报告看着"旧、碎、花、廉价",通常是四件事叠加——①装饰件(标题圆点/小标题竖条/强调块左竖线);②**字阶太碎**(给每个小组件单设字号,同屏七八档正文级字号,眼睛不断重新聚焦);③**加粗过密**(一段五六个 `<strong>`,加粗失去强调意义);④**并列项挤一坨**(①②③各是一段完整论述却塞在一个段落里)。**解法统一是"现代基线":装饰件全去、字阶收敛到正文级同一档、加粗每段≤1-2处、并列长项每项分行**。层级只靠字号/字重/间距 + 留白(见「排版与层级(现代基线)」固化项 + 4 条自检)。
- **坑 11(换配色只改 `:root`,漏了硬编码残留色)**:统一配色时以为改完 `:root` 变量就行,结果 **Tab 栏毛玻璃底、象限图光晕、渐变、半透明 `rgba()`、内联 `style` 里的 hex** 这些**没走变量的硬编码色**还是旧的,导致局部色不搭。**换配色后必须全文搜一遍残留**:`grep` 旧主色/旧底色的 hex 和 rgba(尤其 `rgba(...)`、`background:#...`、`box-shadow`、`linear-gradient`、内联 `style=`),逐个换成新 token 或新色。注意区分:资产库 Tab 里"给频道用的品类设计色板"是设计交付内容,该保留,不是报告皮肤。

## 归档

报告完成后:

1. 内容底稿存到品类目录根下:`{品类目录}/{品类}行业市场分析.md`
2. 渲染成最终交付:`{品类目录}/{品类}行业市场分析.html`(5 Tab 汇报页,规范见「HTML 汇报页输出规范」),过一遍 HTML 汇报页自检
3. 在工作流的 `README.md` 版本历史里追加一行:"YYYY-MM 完成 {品类}中档分析,反馈:XXX"
4. 把踩到的坑更新回工作流对应阶段的"常见坑"节

> **交付 ≠ 结束,主动开深挖闭环**:报告给出后,**主动提示用户"报告里任何一个点想深入,直接说,我带着行业专家视角陪你继续拆"**(如"分类页导购优化""签到玩法图书化"想展开)。用户挑某个点深挖 → 无缝转回**第0档对话态**(拆到模块级 + 配灰阶线框 + 挂设计原则),不必重起流程。把一次性报告变成可持续的行业咨询——这正是"我们是能对话的行业专家,不是一次性报告生成器"。
