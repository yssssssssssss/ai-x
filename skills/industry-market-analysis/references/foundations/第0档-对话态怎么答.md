# 第0档 · 对话态怎么答

> **给 agent 的执行指引:用户只是碰想法、拆一个竞品、要个判断时,不起流程、不产文件,直接在对话里答——但内核不打折。** 这是本 skill 最高频的用法,别把它当"随便聊两句",它和 A/B 档用的是同一套框架和设计哲学,只是产出留在对话里。
>
> **和 A/B 用法的关系**:第0档是"要不要起流程"的开关,轻/中/重是"起了流程做多深"。第0档答完,如果用户说"这个整理成报告",再升到 A(一次产出 `.md`)或 B(分阶段出 HTML)。**别默认冲着出 HTML 走,也别在轻场景硬造文件。**

---

## 什么时候走第0档(先判断,别急着答)

命中任意一条,就走对话态,不起流程:

- 碰一个想法:"图书签到玩法从行业看有什么问题""这个入口该站哪条价值观"
- 拆一个竞品的某个模块 / 要一张对比表 / 要一段灰阶线框描述
- 问某个体验点"违反哪条设计原则"
- 要个快速判断、方向性建议,没说"出报告/整理成文档"

**反例(不该走第0档,该起流程)**:用户明确说"给我一份 XX 品类的行业分析报告""要立项汇报的材料""做频道年度规划"——这类走 A/B,见 `阶段说明/`。

---

## 四条底线(对话态也一条都不能松)

第0档省的是"产出体量",不是"专业标尺"。以下四条和写报告时完全一样:

1. **锚定京东设计哲学做裁判**。别停在"我觉得不好"。诊断问"违反哪条 6 原则",定位问"站哪条价值观(自然/务实/包容/焕新)",设计问"继承平台还是行业增量、增量凭什么"。原则全文见 `京东设计哲学(平台基线).md`。
2. **拆到模块级,不泛谈**。说竞品就拆到"哪个页面的哪个模块怎么做的",不说"它体验好";说问题就指到"哪一屏哪个控件",不说"首页有点乱"。
3. **量化必有出处,绝不编数**。对话里同样不许编 % / ¥ / 增速。有引用给引用,没有就标"估算·待核实"或"【待补】",并说清缺什么、去哪补。**宁可说"这个数我没有",也不许造一个像真的假数。**
4. **给设计师能开工的颗粒度**。方向性建议要落到"具体设计动作",能配一句灰阶线框描述就配(见下"三个即时产出物")。**宁可深讲一两条,不泛列一堆。**

## 三个即时产出物(对话里直接给,不落文件)

用户要什么就给对应那个,别一次全上。

### ① 竞品拆解(拆到模块级)

按四要素答,能省则省,但"核心特征 + 一个具体优点 + 一个具体局限"是底线:

- **核心特征**:它和别家最不一样的一点(一句话)。好:"用评论/评分构建决策辅助,而非单纯展示 SKU";坏:"体验完善,内容丰富"。
- **具体优点/局限**:指到功能层。好:"详情页把差评和好评分开展示,帮用户预判风险";坏:"评论体系完善"。

> 要横向比多个竞品时,直接在对话里给四要素表(项目/核心特征/适配场景/优点/局限),格式见 `模板/对比表-四要素.md`。

### ② 对比表 / 判断

要"A 和 B 哪个好""该走哪个方向"这类,给一张小对比表 + 一句带倾向的结论,结论必须挂设计哲学:

> "推 A。B 的强运营弹层违反【流畅一致】【亲和友好】,打断了决策链路;A 站在'务实'价值观上,让用户更快到达要买的书。"

### ③ 灰阶线框描述(设计动作)

给设计建议时,别停在"可以优化一下首页",要能口述一个灰阶线框:

> "签到入口从首屏浮层改成榜单页顶部的一个常驻条:左侧'连续签到 3 天'文案 + 进度点,右侧一个'签到'主按钮。去掉自动弹窗——把打断式改成用户主动触达,对应【亲和友好】。"

灰阶=只讲结构/层级/位置,不定色彩风格(色彩是阶段6 的事)。

## 一句话结论收尾

第0档答完,习惯性用一句可引用的话收口,方便用户直接拿去用或往上升档:

> "图书签到当前的问题不是奖励不够,而是入口是打断式弹层、违反【亲和友好】——改成常驻触达就能解一大半。要不要我把这块整理成一份轻档分析?"

末尾那句"要不要升档"是可选的引导:**用户没要报告时不主动造文件,但可以提示这条路存在。**

## 常见误区

- **误区 1**:把第0档当闲聊,丢了设计哲学裁判 → 对话态也要能回溯到具体原则/价值观,否则和"随便问问 AI"没区别。
- **误区 2**:为了显得专业,一个小问题也硬起 8 阶段、硬产 HTML → 违背第0档初衷,徒增用户成本。
- **误区 3**:对话里编数凑气势 → 比写报告时更容易犯,因为没有引用规范兜底。**口头回答同样绝不编数。**
- **误区 4**:泛泛给"建议优化下体验" → 没有拆到模块、没有具体设计动作,等于没答。宁可只讲一条但讲透。
