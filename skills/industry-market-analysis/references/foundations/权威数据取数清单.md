# 权威数据取数清单

> **为什么有这份清单**:设计师用这个 skill,图的是"我们比他们更懂行"。行业规模、增速、赛道热度这类硬数据,**光标【待补】就等于承认自己不懂行**——招牌就塌了。这份清单给出**在标【待补】之前必须穷尽的取数通道**,尤其是京东站内一手数据(`o2`),那是别的团队拿不到的真正壁垒。
>
> 配合 `阶段说明/阶段2-外部数据调研.md` 的「取数纪律」用。

## 取数优先级(逐级穷尽,拿不到才降级)

| 优先级 | 通道 | 拿什么 | 壁垒 |
|---|---|---|---|
| **① 京东站内一手** | `o2`:`o2-ge-search` / `oxygen-sku-selection` / `dongmetric` | 本品类站内真实搜索UV/成交/曝光、行业热词榜、类目大盘同比环比、关键词用户画像 | ⭐**别的团队拿不到**,是我们的专家壁垒 |
| **② 公开权威源** | WebSearch / WebFetch | 全行业规模、增速、国民阅读/消费调查 | 通用;且**不能假设 AI 每次能联网**(部分环境 WebSearch 不通) |
| **③ 【待补】兜底** | —— | 标注 + **已试通道说明** | 前两级穷尽才用 |

**一句话红线**:能调 `o2` 就别标【待补】;要标【待补】,得先能说清"① ② 都试过、卡在哪"。

---

## 通道 ① · 京东站内一手数据(o2)

> 前置:先 `o2 login`(京东 SSO),再按各 CLI 的 skill 指南配 ERP/cookie。**首次用先 `--dry-run` 预演 + `doctor` 验权限**,没权限再降级——别硬跑报错就放弃。
> 详细用法随时查:`o2 skill <cli名>`。以下命令语法摘自各 CLI 官方 skill 指南,**类目ID/关键词需按实际品类替换**。

> **⚠️ 实测踩坑(2026-07 图书案例,liuxi1269 账号,亲测)——这些是文档没写、只有跑过才知道的**:
> 1. **登录成功 ≠ 能取数**。`o2 login` 成功、`doctor` 显示 `ready:true`(凭证四项全绿),但真正跑 `search overview` 仍可能返回 `no auth:专用菜单权限校验`(status -1,错误藏在 `result.message`);`oxygen-sku-selection` 返回 `no_data_permission`。**黄金眼/选品的数据接口需要额外的"搜索词分析"菜单权限**,登录态给不了。
> 2. **cookie 不会自动复用**。`o2-ge-search` / `oxygen-sku-selection` 找的是 `~/.oxygen-cli/config.json`,而 `o2 login` 存的是 `~/.o2/config.json` 的 `auth.sso_cookie`。要手动搬:
>    ```bash
>    COOKIE=$(python3 -c "import json;print(json.load(open('$HOME/.o2/config.json'))['auth']['sso_cookie'])")
>    o2-ge-search config set credentials.cookie "$COOKIE"; o2-ge-search config set credentials.erp <你的ERP>
>    oxygen-sku-selection config set credentials.cookie "$COOKIE"; oxygen-sku-selection config set credentials.erp <你的ERP>
>    ```
> 3. **权限申请链接**(选品 CLI 报错里给的):`https://joyspace.jd.com/pages/DxMOjjnHIaq1sKdwd71k`(黄金眼→申请"搜索词分析"菜单)。**取京东站内品类大盘,得先让用户开通这个权限**,别指望登录就够。
> 4. **`org tree` 可能返回空**(组织可见性),`cate tree` 必须带 `--bu-ids`。定位品类 buId/cid 未必顺,做好降级到公开源/用户提供的准备。
> 5. **此沙箱环境 WebSearch 不可用、WebFetch 抓不到报告子页数据、webcli 无通用网页抓取命令**——所以"公开源"通道在纯 AI 环境里往往也断,更凸显:**规模/增速这类数,现实里多半要么开通内部权限、要么用户直接提供**。都拿不到时,走"诚实交代已试通道 + 用结构性趋势替代精确数字"(见下方 ③ 和阶段2)。

### A. o2-ge-search(黄金眼搜索概览)—— 站内大盘 + 用户画像

装/验:
```bash
o2 install o2-ge-search
o2-ge-search --json doctor                        # 验证登录态与权限
o2-ge-search --json cate tree --bu-ids <buId> --dry-run   # 先拿类目树,定位本品类 cid
```

**站内大盘(规模/趋势的一手替代)**——按类目取搜索UV/成交金额/曝光,按月看趋势:
```bash
# 先 dry-run 预演,确认参数
o2-ge-search --json search overview --date 2026-06-01 --group-by cate_1 --interval BY_MONTH --dry-run
# 正式取(把 <buId> 换成图书事业部ID,可用 org tree / cate tree 定位)
o2-ge-search --json search overview --start-date 2026-01-01 --end-date 2026-06-01 --interval BY_MONTH --group-by cate_1 --bu-ids <buId>
```

**关键词用户画像(直接喂养阶段3 用户洞察 B)**——会员等级/购买力/年龄/职业:
```bash
o2-ge-search --json keyword user-age        --start-date 2026-18 --end-date 2026-18 --keyword 图书 --dry-run
o2-ge-search --json keyword purchase-power  --start-date 2026-18 --end-date 2026-18 --keyword 图书 --dry-run
o2-ge-search --json keyword member-level    --start-date 2026-18 --end-date 2026-18 --keyword 图书 --dry-run
o2-ge-search --json keyword user-profession --start-date 2026-18 --end-date 2026-18 --keyword 图书 --dry-run
```
> 日期格式:`overview` 用 `YYYY-MM-DD`;`keyword *` 画像用"周数"格式 `YYYY-WW`(如 2026-18)。
> keyword 画像需在黄金眼后台开通"搜索词下人群"权限,否则 403——见 `o2 skill o2-ge-search` 的 Prerequisites。

### B. oxygen-sku-selection(选品分析)—— 行业热词榜 + 赛道热度

装/验:
```bash
o2 install oxygen-sku-selection
oxygen-sku-selection category tree --json          # 拿类目树,定位本品类 cid1/cid2/cid3
```

**行业搜索热词榜(赛道在热什么、蓝海在哪)**:
```bash
oxygen-sku-selection keyword rank --start "2026-20" --cid1 <cid1> --json
oxygen-sku-selection keyword rank --start "2026-20" --cid1 <cid1> --order-by "blueOcean:desc" --json   # 找蓝海
```

**关键词概览(曝光/UV + 同比环比增速)**——这就是"增速"的一手来源:
```bash
oxygen-sku-selection keyword overview -k "图书" -s "2026-18" --json        # date-type 默认周;lyr=同比 lpr=环比
oxygen-sku-selection keyword overview -k "图书" -s "2026-06" --date-type 2 --json   # 按月
```

**类目/品牌竞争分布(供给侧 C + 竞品 D)**:
```bash
oxygen-sku-selection keyword category -k "图书" -s "2026-18" --order-by "blueOcean:desc" --json
oxygen-sku-selection keyword brand    -k "图书" -s "2026-18" --order-by "uv:desc" --json
```

### C. dongmetric(指标平台)—— 找现成口径指标

```bash
o2 install dongmetric
dongmetric search --query "图书 GMV" --page-size 20 --json    # 搜现成指标,拿 indexCode / 详情页
dongmetric search --query "图书 DAU" --page-size 20 --json
```
> 只读检索:能搜到全站指标(不按身份裁剪),但只给指标定义/链接,取实际数值还得回 A/B 或指标详情页。

## 通道 ② · 公开权威源(o2 拿不到时)

用 WebSearch / WebFetch 抓,**每个数字必带 URL + 时间口径**(见阶段2 做法 A/B)。分品类常用权威源:

| 品类 | 权威源 |
|---|---|
| **图书** | 开卷 BookScan(全国图书零售码洋/增速)、中国新闻出版研究院《全国国民阅读调查》、当当/京东财报 |
| 通用零售 | 艾瑞咨询、QuestMobile、国家统计局、Euromonitor |
| 母婴 | 艾瑞母婴报告、母婴行业观察 |
| 3C/数码 | IDC、Counterpoint、Canalys |
| 美妆 | 青眼、CBNData、欧睿 |

> ⚠️ **不能假设 AI 每次都能联网**:部分运行环境 WebSearch 不通。这时更要靠通道 ①;真都不通,才走 ③。

## 通道 ③ · 拿不到时怎么写(前两级穷尽才用)

**两种合格写法,任选**:

**写法一 · 保留【待补】标签,但必须带"已试通道"**(适合还打算补的):
```
✅ 好:图书线上零售规模【待补·已试:①黄金眼 o2-ge-search 登录成功但数据接口卡"搜索词分析菜单权限"(待申请);②公开源 WebSearch 环境不可用、WebFetch 抓开卷官网无数据页。补数路径:开通黄金眼权限 / 团队提供开卷年报】
❌ 差:图书市场规模【待补】
```

**写法二 · 干脆不用【待补】标签,改成一段诚实交代 + 用结构性趋势替代精确数字**(2026-07 图书案例实采,推荐):
- 一个小字 note 块讲清:这个数属公开权威数据(开卷/新闻出版研究院)、本次已实测穷尽哪些通道、卡在哪、补数路径是什么、"绝不编造";
- 然后**用可确证的行业结构性趋势顶上**——规模数字缺席不影响判断行业格局。**"行业格局看的是结构,不是单一数字"**,这恰恰是"行业专家"比"会查码洋的人"强的地方。

> 核心心法:【待补】不是免死金牌,但也不必执着于凑出那个数字。**拿不到精确数时,专家的价值是把"为什么这个数暂缺 + 不靠它我依然能判断什么"讲清楚**,而不是空一个标签或编一个数。

好处:①诚实(不编数);②给接手人留了"从哪继续补"的线索;③让评审看到"我们尽力了、卡在权限/付费墙",而不是"懒得查";④即使数字永远补不上,报告的行业判断依然立得住。

> **⚠️ 比【待补】更坏的是模糊词**:❌"约数千亿""据估算增长较快""蓬勃发展"——这类词没出处却装成结论,是**伪装的编数**。规则:要么给带出处的真数,要么老实标【待补】,**绝不用模糊词兜底**。另:一章里关键量化点过半(~30%)靠【待补】撑,说明没查透或本不该量化,退回补数或改用结构性判断。

## 自检

- [ ] 硬数据(规模/增速/热度)在标【待补】前,**至少试过 o2 通道 ①**(有 dry-run/doctor 记录或明确的无权限结论)
- [ ] 公开源数字都带 URL + 时间口径
- [ ] 所有【待补】都注明了"已试哪些源、卡在哪"
- [ ] **没有用"约/大约/据估算/蓬勃发展"等模糊词假装有数**(要么真数带源,要么老实【待补】)
- [ ] 能用京东站内一手数据的地方,没用公开均值凑(站内数据更有说服力也更有壁垒)
